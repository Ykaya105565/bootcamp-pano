14 · Day11 – Açık Kaynaklı Modeller

Bu derste ne var: Açık kaynaklı (open-weight) LLM'lerin ne olduğu, lisansları, kapalı modellere göre artı/eksileri ve hangisinin ne zaman seçileceği. Model boyutu–VRAM ilişkisi, kuantizasyon (Q4, Q4_K_M), Dense vs. MoE mimarisi. Uygulamada Ollama ile model indirme/çalıştırma, sohbet içi komutlar, Modelfile ile model türetme ve Claude Code'u lokal modelle başlatma.

Ana kavramlar

  • Parametre / ağırlık (weight) / katsayı — Sinir ağında nöronlar arasındaki bağlantıların sayısal değeri (ondalıklı sayı). "27B model" = 27 milyar parametre. Neden önemli: Modelin hem kalitesini hem bellek ihtiyacını belirler.
  • Açık kaynaklı / açık ağırlıklı model (open-weight LLM) — Ağırlıkları herkese açık yayınlanan model; indirip lokalde çalıştırabilir, üzerine uygulama (AI app, RAG, AI agent) kurabilirsiniz. Mimari açıklanır, ağırlıklar yayınlanır; eğitim kodu ve eğitim verisi genelde açıklanmaz. Neden önemli: Maliyet ve veri gizliliği.
  • Kapalı kaynaklı model — Ağırlıklar sağlayıcıda kalır (Claude, OpenAI, Gemini); sadece API veya arayüz üzerinden kullanılır.
  • Lisans — Açık ağırlık ≠ "istediğimi yaparım". MIT (ör. DeepSeek-R1) ve Apache 2.0 (ör. Qwen3) ticari kullanıma esnek; Llama 4 Community License 700 milyon kullanıcı üzerinde ayrı lisans ister. Neden önemli: Ticari üründe hukuki risk.
  • Harness — Modelin etrafındaki ekosistem (araçlar, terminal erişimi, arayüz). Araba benzetmesi: motor = model, gerisi harness. Claude Code, Hermes Agent, Codex, OpenClaw birer harness. Neden önemli: Aynı açık modeli farklı harness'lere bağlayıp ajan olarak kullanabilirsiniz.
  • VRAM — Ekran kartı belleği; model ağırlıkları buraya yüklenir. Mac'lerde bütünleşik (unified) bellek hem CPU hem GPU tarafından kullanılır.
  • CUDA OOM (Out Of Memory) — VRAM'i ağzına kadar doldurunca alınan hata.
  • Kuantizasyon (quantization) — Ağırlıkların sayısal hassasiyetini düşürerek (FP32 → 4-bit) modeli küçültmek. Az kalite kaybı, büyük bellek kazancı, üstelik daha hızlı.
  • K-Quant (akıllı kuantizasyon) — Hassas parametreleri yüksek, diğerlerini düşük bit ile temsil eder. Q4_K_M = 4-bit, K-quant, Medium şiddet.
  • Dense model — Her soruda tüm katmanlar/ağırlıklar aktif.
  • Mixture of Experts (MoE, sparse) — Router/gating soruyu yalnızca ilgili birkaç "uzmana" (expert) yönlendirir; diğerleri yüklü ama pasif. Daha az hesaplama.
  • Efektif parametre (E2B, E4B) — Gemma 4'te modelin toplam parametresi daha fazla ama çalışırken yalnızca 2B/4B'si aktif; telefon, robot gibi edge cihazlar için.
  • Thinking (düşünen) model — Cevaptan önce akıl yürütme adımı üreten model; Ollama'da açılıp kapatılabilir ya da gizlenebilir.
  • LoRA — Fine-tuning'de yeni parametre eklemeden mevcut parametrelerin bir kısmını güncelleyen teknik; adaptör ~30–40 MB, sonra ana modelle birleştirilir.
  • Modelfile — Ollama'da mevcut bir modelden (FROM) sistem mesajı ve parametrelerle yeni model türetmeye yarayan uzantısız dosya.
  • Guardrails — Modelin zararlı isteklere (silah, kendine zarar) cevap vermemesini sağlayan güvenlik bariyerleri.

Akış / mimari

Basit sinir ağı:

Input → Girdi katmanı → Gizli katman(lar) → Çıktı katmanı → Output
                 (aradaki her bağlantı = 1 parametre)

Hangi LLM?

Veri gizliliği önemli      → Açık kaynaklı
Yüksek hacim + ücret önemli → Açık kaynaklı
Fine-tuning                → Açık kaynaklı
Bilgisayar güçsüz          → Küçük açık model  VEYA  Kapalı model (API)

Açık modellerle çalışma araçları:

Ollama        → modelleri lokale indir + çalıştır
Hugging Face  → uçtan uca ML: Transformers · Datasets · Diffusers · Gradio

Ollama iş akışı:

ollama pull <model> → ollama run <model> → (sohbet: /set, /show, /bye)
   → ollama ps (çalışanlar) → ollama stop <model>
Modelfile → ollama create <yeni_ad> -f Modelfile → ollama run <yeni_ad>
ollama (menü) → Launch Claude Code → lokal model seç

Dense vs MoE:

Dense:  soru → katman1 → katman2 → … → katman8 (8/8 aktif)
MoE:    soru → router/gating (skor + top-k) → uzman1 + uzman5 (2/8 aktif) → sonuçlar birleştirilir

Kod / uygulama

Bu dersin kaynak kod dosyası yok; komutlar ders anlatımından derlendi.

1) Model indirme, listeleme, çalıştırma

ollama list
ollama pull qwen3.5:9b
ollama run qwen3.5:9b
  • list → Bilgisayardaki modelleri gösterir; ilk kurulumda boş gelir.
  • pull → Modeli katman katman indirir; daha önce inen katmanlar tekrar inmez. :9b etiketi boyutu seçer, etiket yoksa latest iner.
  • run → Modeli belleğe (GPU'ya) yükler ve sohbet açar; model yoksa önce indirir.

2) Düşünme modunu yönetme

ollama run gemma4:12b --think=false     # düşünmeden cevap
ollama run gemma4:12b --think           # düşünerek cevap
ollama run gemma4:12b --hidethinking    # düşünür ama düşünmeyi göstermez
  • --think=false → Hızlı, basit sorular için.
  • --hidethinking → Chatbot'larda kullanıcıya düşünme sürecini göstermemek için.

3) Sohbet içi komutlar

/set nothink | /set think        # düşünmeyi kapat/aç (sohbetten çıkmadan)
"""çok satırlı
mesaj"""                          # birden fazla satırlı girdi
/show info                        # mimari, parametre, kuantizasyon
/show license                     # lisans — kullanmadan önce bak!
/set verbose                      # token sayısı, süreler, tok/s istatistikleri
/set system "…"                   # sistem mesajı
/show system                      # mevcut sistem mesajını gör
/set parameter                    # ayarlanabilir parametreleri listele
/set parameter num_ctx 10000      # bağlam penceresini 10 000 token yap
/bye   (veya Ctrl+D)              # çık; Ctrl+C takılan üretimi keser
  • seed → rastgeleliği sabitler (tekrarlanabilir sonuç). temperature, top_k, top_p → yaratıcılık/örnekleme. num_ctx → modelin aynı anda görebileceği token sayısı.

4) Modelfile ile model türetme

FROM gemma4:12b
SYSTEM "Sen bir Python uzmanısın. Türkçe cevap ver."
PARAMETER temperature 0.?        # değer transkriptte anlaşılmıyor

ollama create gemma4-12b-turkce -f Modelfile
ollama run gemma4-12b-turkce
  • Dosya adı Modelfile, uzantısız.
  • FROM → Temel model. Katmanlar paylaşıldığı için yeni model saniyeler içinde oluşur; ollama list 8 GB gösterse de ek disk kullanımı küçüktür.
  • SYSTEM → Modele kalıcı rol verir; her run'da tekrar /set system yazmanız gerekmez.
  • PARAMETER → Varsayılan parametreleri sabitler.

5) Çalışanları izleme ve durdurma

ollama ps                        # çalışan modeller, boyut, %GPU, context, süre
ollama stop gemma4-12b-turkce    # modeli bellekten indir
ollama serve                     # sunucuyu başlat (harness'ler için)
ollama --help                    # tüm komutlar
  • Ollama sunucusu http://localhost:11434 adresinde çalışır ("Ollama is running"). n8n, Hermes vb. bu adresle bağlanır.
  • stop yapılmazsa model VRAM'de kalmaya devam eder.

6) Claude Code'u lokal modelle başlatma

claude --version     # Claude Code kurulu mu?
ollama               # menü → "Launch Claude Code" → listeden lokal model (ör. gemma4:12b)

Hocanın vurguları & pratik kurallar

  • Önce lisans, sonra kullanım. MIT/Apache 2.0 rahat; Llama 4 Community License'ta 700M kullanıcı sınırı var.
  • Bellek hesabı: boyut ≈ parametre sayısı × parametre başına bayt
  • FP32 = 4 B, FP16 = 2 B, INT8 = 1 B, 4-bit = 0,5 B → 10B model: 40 / 20 / 10 / 5 GB.
  • Kaba kural (4-bit): gereken VRAM ≈ B sayısının yarısı + pay. 9B → ~6–7 GB, 27B → ~18 GB+.
  • VRAM'i doldurma: Ağırlıklara VRAM'in ~%65–80'ini ayır. 16 GB kart → ~13–15 GB'lık model değil, güvenli aralık 10–12 GB.
VRAM Model boyutu
8 GB ~5–6 GB
12 GB 7–9 GB
16 GB 10–12 GB
24 GB 16–20 GB
32 GB 22–26 GB
  • Kart referansı (tahta): RTX 5090 = 32 GB, RTX 4090 = 24 GB, RTX 5080 = 16 GB, daha küçükler = 8 GB VRAM.
  • Rahat çalışmak için hedef: En az Qwen 27B'yi çalıştırabilen bir makine (≈24 GB VRAM sınıfı).
  • Kuantizasyon tercihi: Genelde 4-bit; şiddet olarak Medium (Q4_K_M) en dengelisi.
  • Küçük açık modeller akıl yürütme sorularında sık yanılır (oto yıkama sorusu). Kritik işler için büyük model veya kapalı model düşün.
  • Production'da düşünme turuna sınır koy (ör. 3–5); küçük modeller düşünürken takılabiliyor.
  • Mac kullanıcıları: Varsa MLX sürümünü indir.
  • Terminale erişen ajanlar: İzinleri dikkatli aç; mümkünse VPS'te veya kişisel veri olmayan ayrı bir makinede çalıştır.
  • Fiyat/performans: Ollama Cloud'daki büyük açık modeller (ücretsiz katman + ~20 $ plan) kapalı modellere ucuz bir alternatif olarak değerlendirilebilir.
  • Yapay zekâ ile emek: Her şeyi modele yaptırma; yazdığını modele değerlendirt, asistan gibi kullan.

Sık hatalar / karşılaşılan sorunlar

  • Model düşünürken takılıyor / çok uzun yazıyor → Ctrl+C ile kes, /bye ile çık, tekrar ollama run. Gerekirse --think=false.
  • Bir öğrencide "merhaba"ya düşünme kısmı görünmedi → Tekrar denenince düşünme çıktısı geldi; geçici davranış.
  • ollama stop modeli bulamadı → Model adı yanlış yazılmıştı; ollama ps'teki tam adı kullan.
  • Model kapatılmadığı için VRAM dolu kalıyor → ollama ps ile kontrol et, ollama stop ile kapat.
  • ollama menüsü hemen gelmiyor → İlk açılışta karşılama ekranı çıkıyor; Enter'a bas.
  • Claude Code başlatılırken "Waiting for sign-in to complete" → Listeden bulut model yerine en alttaki lokal modeli seç.
  • "auto-update failed" uyarısı → Claude Code'u/npm'i güncellemek gerekebilir.
  • 16 GB kartta 27B model çok yavaş → Model VRAM'e sığmayıp sistem RAM'ine taşıyor; daha küçük model veya daha agresif kuantizasyon seç.
  • Tahtadaki yazım hatası: "Float32 → 8 Byte, Float16 → 4 Byte" yazıyor; doğrusu FP32 = 4 bayt, FP16 = 2 bayt (hesaplar doğru değerlerle yapıldı).

Kendini test et

  1. "Açık kaynaklı model" denince tam olarak ne açıktır, ne genelde açık değildir?
Cevap

Mimari açıklanır ve model ağırlıkları yayınlanır. Eğitim kodu ve eğitim verisi genelde açıklanmaz. Modeli çalıştırmak için ağırlıklar yeterlidir.

  1. Llama 4 Community License'ı MIT/Apache 2.0'dan ayıran nedir?
Cevap

Ticari kullanıma izin verir ama uygulama 700 milyon kullanıcıyı aşınca Meta'dan ayrı bir lisans alınması gerekir. MIT ve Apache 2.0'da böyle bir eşik yoktur.

  1. 10 milyar parametreli bir model FP16 ve 4-bit'te kaç GB tutar?
Cevap

FP16: 10 × 2 B = 20 GB. 4-bit: 10 × 0,5 B = 5 GB.

  1. 16 GB VRAM'li bir kartta neden 16 GB'lık bir model çalıştırılmamalı? Hangi aralık güvenli?
Cevap

VRAM'e yalnızca ağırlıklar değil, ayar dosyaları, çalışma belleği, CUDA/Ollama ve diğer programlar da yüklenir; VRAM dolarsa CUDA OOM hatası alınır. Güvenli model boyutu yaklaşık 10–12 GB.

  1. Q4_K_M etiketindeki Q4, K ve M ne anlama gelir?
Cevap

Q4: 4-bit kuantizasyon. K: akıllı kuantizasyon (K-Quant), yani hassas parametreler daha yüksek bitle tutulur. M: Medium sıkıştırma şiddeti, yani hassas katmanlar Q6_K, diğerleri Q4_K.

  1. Dense ve MoE modeller arasındaki fark nedir? MoE'de router nasıl karar verir?
Cevap

Dense'te her soruda tüm katmanlar aktiftir. MoE'de router/gating her uzmana bir uygunluk skoru verir (softmax), en iyi top-k uzmanı seçer; yalnızca onlar hesaplama yapar, sonuçlar birleştirilir. Load balancing uzmanların dengeli eğitilmesini sağlar.

  1. Gemma 4 E4B'deki "E" ne demek, bu modeller nerede kullanılır?
Cevap

Efektif parametre: model toplamda daha büyüktür ama çalışırken yalnızca ~4 milyar parametre aktiftir. Telefon, robot gibi edge cihazlarda kullanılır.

  1. Chatbot'ta modelin düşünmesini istiyor ama kullanıcıya göstermek istemiyorsunuz. Hangi seçeneği kullanırsınız?
Cevap

ollama run <model> --hidethinking

  1. Modelfile ile türetilen model neden saniyeler içinde oluşur ve neden 8 GB görünse de diskte o kadar yer kaplamaz?
Cevap

Temel modelin mevcut katmanlarını yeniden kullanır; yalnızca sistem mesajı/parametre gibi birkaç küçük yeni katman ekler. Ağırlık katmanları ana modelle paylaşılır.

  1. Kapalı modellerin dört dezavantajını ve açık modellerin üç dezavantajını sayın.
Cevap

Kapalı: ücretli, kullanım limitleri, veriler sağlayıcıya gider, internet gerekir. Açık: kapalı modellerden bir tık geride, kurulum gerekir, güçlü bilgisayar gerekir.

  1. LoRA ile fine-tuning'de modele yeni parametre eklenir mi?
Cevap

Hayır. Mevcut parametrelerin bir kısmı güncellenir; bu güncelleme (~30–40 MB) ayrı saklanıp ana modelle birleştirilir.
