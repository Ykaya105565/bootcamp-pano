Ana kavramlar

Rol ve alan - AI Engineer (yapay zekâ mühendisi): Hazır büyük dil modellerini (Claude, GPT, Qwen, DeepSeek) alıp etraflarına uygulama/sistem kuran kişi. Neden önemli: Model eğitmek değil, modelin etrafındaki AI sistemini kurmak işin özü — bu, bootcamp'in bakış açısını belirliyor. - Veri bilimci vs ML mühendisi vs AI mühendisi: Veri bilimci sıfırdan model eğitir; ML mühendisi eğitilmiş modelle uçtan uca proje yapar; AI mühendisi LLM'lerle uygulama yapar ve onu production'da izler (güvenlik, maliyet, doğruluk). Neden önemli: Mülakatlarda sık sorulan ayrım.

1. Aşama - Sanal ortam / uv: Projeye özel izole Python ortamı; uv ile ortam kurmak ve proje yönetmek kolaylaştı. Neden: Bağımlılık çakışmalarını önler (bootcamp boyunca kullanılacak). - Supabase: PostgreSQL tabanlı bulut veritabanı; hocanın AI projeleri için önerisi. - Git / GitHub: Git sürüm takibi aracı; GitHub projelerin barındırıldığı platform. İkisi aynı şey değildir. - API temel kavramları: HTTP, GET/POST, JSON isteği, kimlik doğrulama, API anahtarı. Neden: Modellere ve araçlara erişimin tamamı API üzerinden.

2. Aşama - Transformer: 2017'de Google ekibinin geliştirdiği encoder–decoder mimarisi; neredeyse tüm LLM'lerin temeli. - Prompt: Modele verilen talimat. - Context (bağlam): Modele giden her şey — sistem prompt'u, önceki konuşmalar, tool çıktıları, dokümanlar. - Context engineering: Bu bağlamın tamamını bilinçli tasarlama. Neden: Hocaya göre kötü uygulamaların asıl sebebi kötü model değil, kötü bağlam. - Kapalı kaynak model: API ile erişilir, ücretlidir, veri sağlayıcıya gider. - Açık kaynak model: Lokalde çalışır, ücretsiz ve limitsizdir, veri dışarı çıkmaz. Araçlar: Ollama, Hugging Face. - VRAM: GPU belleği; lokal modelin sığıp sığmayacağını belirler. - Quantization: Modeli VRAM'e sığdırmak için sıkıştırma. - Fine-tuning: Modeli belirli bir alanda uzmanlaştırmak için ağırlıklarını güncellemek. - LoRA / QLoRA: Yalnızca belirli parametreleri eğiten pratik fine-tuning teknikleri; daha kısa eğitim, daha az yer.

3. Aşama - LangChain: LLM uygulaması geliştirme framework'ü. LangGraph = ajanlar, Deep Agents = karmaşık ajanlar, LangSmith = izleme ve değerlendirme. - RAG (Retrieval-Augmented Generation): Modelin bilmediği (ör. şirket içi) bilgiyi, ilgili parçaları getirip bağlama ekleyerek kullandırmak. Neden: Tüm bilgiyi modele vermek pahalı; RAG halüsinasyonu azaltır. - Chunk (parça): Dokümanların bölündüğü küçük metin parçası. - Embedding: Metnin sayısal (vektör) temsili. - Vektör veritabanı: Embedding'lerin saklandığı veritabanı. - Semantic search (anlamsal arama): Girdiye anlamca en yakın vektörleri bulma. - İleri RAG teknikleri: chunking stratejileri, hybrid search, reranking, query rewriting, multi-query. - AI Agent: Görevi yerine getirmek için karar veren, araç kullanan, düşünen ve aksiyon alan (API çağrısı, DB sorgusu, dosya okuma, kod çalıştırma) sistem. Chatbot yalnızca cevap verir; agent karar verir. - Agent workflow kavramları: planning, memory, state, human-in-the-loop, error handling. - MCP (Model Context Protocol): Anthropic'in 2024'te geliştirdiği, AI uygulamalarını dış dünyaya (GitHub, veritabanı, Slack) bağlayan protokol. Bileşenler: host, client, server. - FastAPI / LangGraph Server: Uygulamayı API'ye çevirme araçları. - Docker: Uygulamayı her ortamda çalışacak şekilde paketleme. - CI/CD: Değişiklikleri otomatik test edip otomatik yayına alma. - Observability (gözlemlenebilirlik): Hangi prompt, hangi model, hangi tool, kaç token, hangi adım hata verdi — bunları izleme. - Evaluation (değerlendirme): Test veri seti + test soruları + beklenen sonuçlar ile ölçüm. RAG → retrieval kalitesi; agent → görevi tamamladı mı; LLM çıktısı → LLM-as-a-Judge. - Security: prompt injection, guardrails, API key güvenliği, gereksiz yetki vermeme. - Cost: model seçimi, caching, prompt optimizasyonu, token takibi.

4. Aşama - Portföy: CV'ye yazmak yerine projeyle göstermek. - Görünürlük: Paylaşım, açık kaynak katkısı, konferans, network.

Akış / mimari

AI mühendisinin işi (çizim)

LLM (Claude / GPT / Qwen)
   → uygulama geliştir (API · Tools · MCP · AI agents · RAG)
   → Production
   → uygulamayı izle (güvenlik · maliyet · doğru çalışıyor mu?)

Context'in bileşenleri (çizim)

Sistem prompt'u + önceki konuşmalar + tool bilgileri + dokümanlar  →  CONTEXT  →  LLM
Kötü uygulama  ≠ kötü model   →   = kötü context

Model seçimi (çizim)

Modeller
├─ Kapalı kaynak (GPT, Claude) → API ile iletişim → paralı → veri sağlayıcıya gider
└─ Açık kaynak (Gemma, Qwen)   → lokal çalışır → ücretsiz → veri güvende → Ollama / Hugging Face → model indir
                                  └─ model boyutları → VRAM → Quantization

Kendi verinle çalışmak (çizim)

Kendi verin ─┬─ RAG
             └─ Fine-tuning (belirli alanda uzman LLM) ─┬─ LoRA
                                                         └─ QLoRA   → sadece belirli parametreler eğitilir

Temel RAG hattı (Basic RAG Pipeline) (çizim)

İndeksleme:   Documents → (data loading) → Text chunks → (embedding) → Vector embeddings → Vector DB
Sorgu:        User query → Vector embedding → Vector DB'de arama (retrieval) → Top-K chunks
              Top-K chunks + User query → LLM (generation) → Response

AI Agent → karar verir ─┬─ Tools
                        ├─ Düşünür
                        └─ Aksiyon ─ API çağrısı · DB sorgusu · dosya okuma · kod okuma/çalıştırma

Tek agent  →  Multi-agent

MCP

Kendini test et

  1. Veri bilimci, ML mühendisi ve AI mühendisinin işini birer cümleyle ayırt edin.
Cevap

Veri bilimci sıfırdan model eğitir/geliştirir; ML mühendisi eğitilmiş modellerle uçtan uca proje kurar; AI mühendisi hazır LLM'leri alıp etraflarına uygulama/sistem kurar (API, tools, MCP, agents, RAG) ve production'da güvenlik, maliyet, doğruluk açısından izler.

  1. Context engineering neden prompt engineering'in yerini aldı? Context hangi bileşenlerden oluşur?
Cevap

Modele yalnızca talimat (prompt) gitmediği anlaşıldı. Context = sistem prompt'ları + önceki konuşmalar + tool'lardan gelen bilgiler + dokümanlar. Kötü uygulamaların asıl sebebi kötü context olduğu için tüm girdiyi tasarlamak gerekiyor ("garbage in, garbage out").

  1. Kapalı ve açık kaynak modellerin avantaj/dezavantajlarını karşılaştırın; açık kaynak için hangi iki araç önerildi?
Cevap

Kapalı (GPT, Claude): API ile erişim, ücretli, veri sağlayıcıya gönderilir. Açık (Gemma, Qwen): lokal çalışır, ücretsiz ve limitsiz, veri dışarı çıkmaz. Araçlar: Ollama ve Hugging Face.

  1. Quantization hangi problemi çözer?
Cevap

Lokalde çalıştırılan modelin VRAM'e sığması için modeli sıkıştırır; açık kaynak modelleri daha verimli kullanmayı sağlar.

  1. Kendi verinizle çalışmanın iki yolu nedir? LoRA/QLoRA'nın avantajı nedir?
Cevap

RAG ve fine-tuning. LoRA/QLoRA modelin tüm ağırlıkları yerine yalnızca belirli parametreleri eğitir; eğitim süresi kısalır ve daha az yer kaplar.

  1. Temel RAG'in iki aşamasını adım adım yazın.
Cevap

(1) İndeksleme: doküman → chunk'lara böl → embedding → vektör veritabanına kaydet. (2) Getirme ve üretim: kullanıcı sorusu → embedding → vektör DB'de en yakınları bul → sırala (top-K) → soru + bulunan parçalar LLM'e → cevap.

  1. Hocanın saydığı beş ileri RAG tekniği hangileri?
Cevap

Chunking stratejileri, hybrid search, reranking, query rewriting, multi-query.

  1. Bir chatbot ile AI agent arasındaki fark nedir? Agent workflow'da öğrenilmesi gereken beş kavramı sayın.
Cevap

Chatbot yalnızca cevap verir; agent görevi yerine getirmek için karar verir, tool kullanır, düşünür ve aksiyon alır (API çağrısı, DB sorgusu, dosya okuma, kod çalıştırma). Kavramlar: planning, memory, state, human-in-the-loop, error handling.

  1. Hocanın önerdiği öğrenme sırası (API'den MCP'ye) nedir? MCP'nin üç bileşeni nelerdir?
Cevap

API → Tool Calling → AI Agent → MCP. Bileşenler: host (AI uygulaması, ör. Claude/ChatGPT), client (host ile server arasındaki bağlantı), server.

  1. Production'da bir RAG uygulamasını, bir agent'ı ve genel LLM çıktısını nasıl değerlendirirsiniz? Maliyeti düşürmenin dört yolu nedir?
Cevap

Önce test veri seti, test soruları ve beklenen sonuçlar hazırlanır. RAG → retrieval kalitesi; agent → görevi tamamladı mı; LLM çıktısı → LLM-as-a-Judge. Maliyet: model seçimi (basit işe küçük model), caching, prompt optimizasyonu, token takibi.

Hocaya sorulacaklar / belirsiz kalanlar

  • MCP server tanımı: Transkriptte server "host'un bağlandığı, esasında AI uygulaması" gibi karışık anlatılıyor. Standart tanımda AI uygulaması host'tur; server ise dış sistemin (GitHub, DB, Slack) yeteneklerini sunan taraftır. Hocanın kastı netleştirilebilir (MCP haftasında).
  • Transformer'da "encoder kodlar, decoder işler" ifadesi oldukça yüzeysel; GPT/Claude gibi modellerin decoder-only olduğu ayrımı derste geçmiyor. (Not: 1. hafta LLM dersinde muhtemelen detaylanacak.)
  • "RAG halüsinasyonu çözer" ifadesi: Pratikte azaltır, tamamen ortadan kaldırmaz; hocanın bu konudaki görüşü sorulabilir.
  • Gemma/Qwen ve "Google tarafından geliştirilen": Altyazıda Google ifadesi Qwen'e bağlanmış görünüyor; Gemma Google'ın, Qwen Alibaba'nın modelidir (muhtemelen söyleyiş/altyazı kayması).
  • Deep Agents: Transkriptte "agent kütüphanesi" diye geçiyor; adı çizimden (Deep Agents) alındı.
