15 · HuggingFace ile Çalışmak

Bu derste ne var: HuggingFace Hub'ı (Models, Datasets, Spaces, model kartı) tanıyıp transformers.pipeline ile birkaç satırda metin duygu analizi, görüntüden duygu ve yaş tahmini yapıldı; Gradio ile basit bir arayüz kuruldu. Dersin ikinci yarısında deployment (canlıya alma) projesine başlandı: Supabase'de proje açıldı, SQL ile RLS korumalı bir tablo oluşturuldu ve Python'dan bağlanıp veriler okundu.

Ana kavramlar

  • HuggingFace — Açık kaynak modeller, veri setleri ve demo uygulamaları için merkezi platform ve uçtan uca ML framework'ü (2017'de chatbot şirketi olarak kuruldu). Neden önemli: 3M+ model, 1M+ veri seti; açık modellerle çalışmanın fiili standardı (Ollama ile birlikte).
  • transformers kütüphanesi — Transformer tabanlı modelleri indirip çalıştırmayı kolaylaştıran kütüphane; artık ağırlıklı olarak PyTorch üzerine (TensorFlow desteği kaldırıldı, JAX var).
  • Framework vs kütüphane — Hiyerarşi: modül → kütüphane → framework. Framework birden fazla kütüphaneyi kapsar.
  • pipeline — Görev (task) + model adı verilince modeli ve tokenizer'ını birlikte indirip kullanıma hazırlayan üst düzey API. Neden önemli: Her modelin kendi tokenizer'ı var; pipeline eşleştirmeyi sizin yerinize yapar. Model verilmezse görevin varsayılan modeli iner.
  • Task (görev) — text-classification, image-classification, object detection, image segmentation, video classification, text-to-video vb. Hub'da modeller görevlere göre filtrelenir.
  • Model kartı (Model Card) — Modelin açıklaması, kullanım kodu, dosyaları ve config.json'ı. Neden önemli: Modelin hangi etiketleri tahmin ettiğini ve nasıl girdi beklediğini buradan öğrenirsiniz.
  • config.json — Model ayarları: etiketler (id2label), model tipi, aktivasyon fonksiyonu, girdi beklentileri.
  • safetensors vs .bin — Ağırlık dosya formatları; safetensors HuggingFace'in geliştirdiği yeni format, .bin eski PyTorch formatı. Model indirmek = ağırlıkları indirmek.
  • BERT / DistilBERT — Transformer'ın encoder kısmından (Google, 2018) gelen, sınıflandırma için kullanılan model; DistilBERT onun küçük versiyonu. GPT ise decoder tabanlıdır (metin üretimi).
  • Not: DistilBERT knowledge distillation ile küçültülmüştür (hoca "quantize hali gibi" benzetmesini yaptı).
  • Spaces — HuggingFace'te barındırılan demo uygulamalar (Gradio/Streamlit); kodları açık, GitHub gibi katkı yapılabilir.
  • Gradio — Notebook içinde bile birkaç satırla arayüz kuran kütüphane; Streamlit'ten daha basit.
  • CUDA — NVIDIA'nın matematiksel işlemleri GPU'da çalıştırmayı sağlayan platformu; PyTorch'un GPU'lu sürümü için gerekli. Mac'te karşılığı MPS.
  • HF önbelleği (cache) — ~/.cache/huggingface/hub; model bir kez iner, sonra yeniden kullanılır. Zamanla büyür (hocada 29 GB).
  • Deployment (canlıya alma) — Uygulamayı herkesin erişebileceği şekilde yayınlamak.
  • Supabase — PostgreSQL tabanlı bulut veritabanı; pgvector eklentisiyle vektör veritabanı olarak da kullanılabilir. Ücretsiz plan küçük projelere yeter.
  • RLS (Row Level Security, satır düzeyi güvenlik) — Tablo satırlarına kimin erişebileceğini policy'lerle kısıtlar. Bu derste sadece service_role erişebiliyor.
  • Publishable key vs Secret key — Supabase'de publishable key (sb_publishable_...) istemci tarafı içindir ve RLS'e takılır; secret key (sb_secret_...) backend/servis rolüdür. Backend kodunda secret key kullanıldı.
  • LangSmith — LangChain ekosisteminde uygulamaları izleme/tracing aracı (projede kullanılacak).

Akış / mimari

HuggingFace ile model kullanma akışı

Hub → Task filtresi → model seç (indirme sayısı/beğeni/yükleyen) → model kartı + config.json oku
    → pipeline(task, model) → girdiyi modele uygun hale getir (örn. RGB) → tahmin

Görüntü sınıflandırma (duygu/yaş)

Image.open(yol) → .convert("RGB") → pipeline("image-classification", model) → [{label, score}, ...]

Gradio arayüzü

fonksiyon (transform_image) → gr.Interface(fn, inputs, outputs) → demo.launch() → (isteğe bağlı) HF Spaces

Deployment projesi yol haritası (bu ders başlandı, sonraki derste devam)

Kurulum (uv init, paketler, .env) → Supabase (proje, tablo, RLS, bağlantı) → LangSmith (izleme)
  → Vektör DB (pgvector) → Tool → LangGraph agent → İzleme → Streamlit arayüzü → Deploy

Model: OpenAI · Vektör DB: Supabase · Agent: LangGraph · İzleme: LangSmith.

Vektör aramasının mantığı (gelecek ders)

Metin → token → vektör (embedding) → Supabase'e kaydet → sorgu vektörüne en yakın vektörleri bul

Supabase bağlantısı

.env (SUPABASE_URL, SUPABASE_SECRET_KEY, DATABASE_URL) → load_dotenv() → create_client() → table().select().order().execute()

2) Metin duygu analizi

from transformers import pipeline

classifier = pipeline(
    'text-classification',
    model="distilbert/distilbert-base-uncased-finetuned-sst-2-english"
)
classifier("I really enjoyed this movie.")
  • 'text-classification' → görev; pipeline'a ne tür ön/son işlem yapacağını söyler.
  • model=... → Hub'daki model kimliği (kullanıcı/model). Verilmezse varsayılan model iner.
  • Model SST-2 (İngilizce film yorumu duygu veri seti) üzerinde fine-tune edilmiş → çıktı POSITIVE/NEGATIVE + skor. Sonuç: POSITIVE ≈ 0.99.

3) Gradio ile siyah-beyaz dönüştürücü

from skimage.color import rgb2gray

def transform_image(img):
    return rgb2gray(img)

import gradio as gr

demo = gr.Interface(
    fn=transform_image,
    inputs=gr.Image(),
    outputs="image"
)
demo.launch()
  • rgb2gray → RGB diziyi gri tonlamaya çevirir; burada model yok, saf görüntü işleme.
  • gr.Interface → fonksiyonu girdi/çıktı bileşenleriyle sarar.
  • inputs=gr.Image() → kullanıcıdan resim yükleme alanı; resmi NumPy dizisi olarak fonksiyona verir.
  • outputs="image" → dönen diziyi resim olarak gösterir.
  • demo.launch() → notebook içinde ve yerel linkte arayüzü başlatır.

7) Supabase bağlantı testi (2_test_supabase.py)

import os
from dotenv import load_dotenv
from supabase import create_client

load_dotenv()

supabase = create_client(
    os.environ["SUPABASE_URL"],
    os.environ["SUPABASE_SECRET_KEY"],
)

response = (
    supabase.table("students")
    .select("id, name, course")
    .order("id")
    .execute()
)

for student in response.data:
    print(f"{student['id']} | {student['name']} | {student['course']}")
  • load_dotenv() → .env'deki anahtarları os.environ'a yükler; anahtarlar koda gömülmez.
  • os.environ["..."] → köşeli parantezle erişim: değişken yoksa hemen KeyError verir (sessizce None ile devam etmez).
  • create_client(url, key) → Supabase istemcisi; secret key ile RLS policy'sindeki service_role olarak bağlanır.
  • .table("students").select(...) → SELECT id, name, course FROM students.
  • .order("id") → ORDER BY id.
  • .execute() → sorguyu gönderir; satırlar response.data içinde liste/sözlük olarak gelir.
  • for ... → her satırı id | name | course biçiminde yazdırır.

Çalıştırma: uv run supabase.py

SQL tarafında yapılanlar (kod ders dosyalarında yok, anlatımdan): public.students tablosu (id otomatik artan primary key, name text, course text not null) → 3 örnek kayıt INSERT → enable row level security → yalnızca service_role için policy.

Hocanın vurguları & pratik kurallar

  • Birkaç satırla büyük model: pipeline HuggingFace'in en güçlü yanı; önce onu kullanın.
  • Model seçerken indirme sayısına, beğeniye ve yükleyene bakın. Aynı isimli kopyalar hatalı olabilir (45 indirmeli kopya hata verdi, 150 bin indirmeli orijinal çalıştı).
  • Model kartını ve config.json'ı okuyun: etiketler ve beklenen girdi formatı orada.
  • Girdiyi modele uydurun: görüntüde .convert("RGB").
  • Kopyala → çalıştır → anla → değiştir → yayınla: Spaces'teki açık kaynak uygulamalardan öğrenin; kendi versiyonunuzu GitHub/HF/CV'ye koyun.
  • Kaggle: haftalık 30 saat ücretsiz GPU; Expert/Master/Grandmaster unvanları ve yarışmalar işe alımda fark yaratıyor.
  • Colab: güçlü bilgisayarı olmayanlar için; GPU seçmeyi unutmayın (A100 iyi).
  • Conda vs uv: uv daha hızlı (Rust); Conda'yı da bilin. Her proje için ayrı sanal ortam.
  • PyTorch kurulumu: pytorch.org'dan OS + pip + CUDA seçin; Windows'ta pip3 → pip; GPU'lu sürümün kurulduğunu doğrulayın.
  • Donanım: Mac 32 GB birleşik bellek bu kurs için yeterli (27B model bile çalışır, ama NVIDIA'dan yavaş). Ciddi iş için RTX 5090.
  • Önbelleği arada temizleyin (hocada 29 GB).
  • AI ile geliştirme: Planı güçlü modelle (Opus), kodlamayı ucuz modelle yaptırın; tasarımı önce kendiniz şablonlayın (Canva/Figma) ki sonuç "slop" olmasın.
  • Agent'larla araştırma: Bir agent yapsın, başka bir agent/model denetlesin; ama ne yapıldığını mutlaka anlayın ve kendi ifadelerinizle yazın.
  • Supabase: Bölgeyi yakın seçin; DB şifresini saklayın; backend'de secret key; RLS'i SQL ile açın.
  • Bitirme projesi: Gelecek cumartesiye kadar; önerilen listeden ya da derste yapılanı geliştirerek (örn. Streamlit arayüzü ekleyerek). Proje = başarı sertifikası.

Kendini test et

  1. pipeline kullanmanın, modeli elle yüklemeye göre iki temel kolaylığı nedir?
Cevap

Modeli ve o modele ait tokenizer'ı birlikte indirir/eşleştirir; görev için gerekli ön-işleme ve son-işlemeyi (etiket + skor çıktısı) otomatik yapar. Model verilmezse görevin varsayılan modelini kullanır.

  1. BERT ile GPT, Transformer mimarisinin hangi parçalarından gelir ve tipik kullanımları nedir?
Cevap

BERT encoder tabanlıdır (metin sınıflandırma gibi anlama görevleri); GPT decoder tabanlıdır (metin üretimi). DistilBERT, BERT'in küçültülmüş versiyonudur.

  1. Görüntüyü modele vermeden önce neden .convert("RGB") yapıldı ve modelin ne beklediğini nereden öğrenirsiniz?
Cevap

Model 3 kanallı girdi bekler; resim gri (1 kanal) ya da RGBA (4 kanal) olabilir. Beklenen formatı model kartındaki Files → config.json (ve preprocessor ayarları) gösterir.

  1. Yaş modelinde "Invalid model index" hatası neden alındı, model seçerken neye dikkat etmeli?
Cevap

Aynı isimli, başka bir kullanıcının yüklediği (45 indirmeli) hatalı bir kopya seçildi. İndirme sayısı, beğeni ve yükleyen hesaba bakarak orijinal modeli (≈150 bin indirme) seçmek gerekir.

  1. HuggingFace modelleri nereye iner, hf download ile indirmek zorunlu mu?
Cevap

~/.cache/huggingface/hub önbelleğine iner ve tekrar kullanılır. Zorunlu değil; pipeline modeli kendisi indirir. hf auth login da çoğu açık model için gerekmez, yükleme (upload) için gerekir.

  1. gr.Interface'in üç temel parametresi nedir ve bu örnekte neyi temsil eder?
Cevap

fn (çalışacak fonksiyon: transform_image), inputs (girdi bileşeni: gr.Image()), outputs (çıktı tipi: "image"). demo.launch() arayüzü başlatır.

  1. Supabase'e bağlanmak için .env'de hangi üç değişken oluşturuldu, her biri nereden alınır?
Cevap

SUPABASE_URL (Connect → Project URL), SUPABASE_SECRET_KEY (Project Settings → API Keys → secret key, sb_secret_...), DATABASE_URL (Connect → Direct → Session pooler connection string; [YOUR-PASSWORD] yerine şifre, köşeli parantezsiz).

  1. Bağlantı başarılı olduğu halde response.data boş geliyorsa en olası neden nedir?
Cevap

Publishable key kullanılmıştır. RLS açık ve policy yalnızca service_role için tanımlı olduğundan publishable key satırları göremez. Secret key kullanılmalı. (Ayrıca dosyanın kaydedildiği kontrol edilmeli.)

  1. RLS nedir, bu derste nasıl yapılandırıldı?
Cevap

Satır düzeyi güvenlik; tablo satırlarına erişimi policy'lerle sınırlar. students tablosunda RLS açıldı ve sadece backend rolü service_role için erişim policy'si tanımlandı.

  1. Deployment projesinin bileşenleri ve sırası nedir?
Cevap

Kurulum → Supabase (DB + bağlantı) → LangSmith (izleme) → vektör DB (pgvector) → tool → LangGraph agent → izleme → Streamlit arayüzü. Model OpenAI, vektör DB Supabase.
