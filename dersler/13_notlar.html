13 · Day10-MCP

Bu derste ne var: Önce function calling (fonksiyon çağırma) OpenAI Responses API ile adım adım uygulandı: modelin araç seçmesi, uygulamanın aracı çalıştırması, sonucun modele geri verilmesi. Ardından aynı add fonksiyonu bir MCP sunucusuna çevrildi, MCP Inspector'da test edildi, sunucuya tool / resource / prompt eklendi. Son olarak MCP mimarisi (Host–Client–Server) anlatıldı ve sunucu mcp.json ile VS Code'a bağlanıp sohbet panelinden kullanıldı.

Ana kavramlar

  • LLM çağrısı (LLM call): Tek LLM, araç yok (klasik chatbot). Önemi: En basit katman; modelin bilgisi eğitim kesim tarihiyle sınırlı.
  • Araç (tool): LLM'in dış dünyayla iletişim kurmasını sağlayan fonksiyon/servis (hesap makinesi, web arama, hava durumu, veritabanı, dosya sistemi, API). Önemi: Güncel bilgi ve deterministik hesap (LLM'ler olasılıksal token tahmincisi olduğu için çarpmayı bile yanlış yapabiliyordu).
  • Fonksiyon çağırma (function calling): Modelin, araç açıklamalarına bakarak hangi aracı hangi parametrelerle çağıracağına karar verip bunu uygulamaya bildirmesi. Önemi: Aracı model değil, uygulama çalıştırır; model sadece seçim ve parametre üretir.
  • Agentic sistem: Düşünen, plan yapan, gerektikçe tekrar araca giden, bilgiyi hafızaya alan ve aksiyona geçen sistem. Önemi: ChatGPT/Claude/Gemini'nin arkasındaki yapı; hoca 2026'yı "agentic yılı" olarak niteledi.
  • MCP (Model Context Protocol): Anthropic'in 2024 sonunda çıkardığı, AI uygulamalarını araç ve veri kaynaklarına bağlamak için standart iletişim protokolü. Önemi: Her uygulama–araç çifti için ayrı entegrasyon yazma yükünü kaldırır. Artık OpenAI, Google vb. de kullanıyor; fiilî standart.
  • MCP ≠ daha zeki model: MCP modeli akıllandırmaz; yalnızca bağlantı ve iletişim katmanıdır.
  • MCP = function calling'in genişletilmiş, standartlaşmış hâli.
  • M × N problemi: 3 uygulama × 5 araç = 15 entegrasyon; araya MCP katmanı koyunca tek standart yeterli.
  • Tools / Resources / Prompts (MCP'nin üç temel yapısı):
  • Tools: Çağrılabilir araçlar (aksiyon).
  • Resources: Modele verilen ek bilgi/bağlam (URI ile adreslenir, ör. course://mcp).
  • Prompts: Parametreli hazır prompt şablonları.
  • Host: AI uygulamasının kendisi (Claude Desktop, VS Code, Streamlit uygulaması); LLM'i çalıştırır, kullanıcıyla konuşur.
  • Client: Host içinde, bir MCP sunucusuyla bağlantıyı yöneten bileşen. Host birden fazla sunucuya bağlanabilir.
  • Server: Tool/resource/prompt'ları dış dünyaya standart biçimde sunan program.
  • Transport stdio: Host ile sunucu arasında standart girdi/çıktı üzerinden iletişim (yerel süreç olarak çalıştırılır).
  • MCP Inspector: uv run mcp dev <dosya> ile tarayıcıda açılan test arayüzü; Node.js gerektirir.
  • mcp.json: Host'a (VS Code) hangi sunucunun nasıl başlatılacağını söyleyen yapılandırma dosyası.
  • A2A (Agent2Agent): Google'ın geliştirdiği, ajanlar arası iletişim için standartlaşan protokol (derste yalnızca adı geçti).

Akış / mimari

Function calling akışı:

Kullanıcı → Uygulama → Model (araç seç + parametre üret)
        → Uygulama (fonksiyonu ÇALIŞTIRIR) → Model (sonuçla cevap üret)
        → Uygulama → Kullanıcı

Koddaki karşılığı:

input_list[user] → responses.create(tools) → output: function_call
→ input_list += output → json.loads(arguments) → add(**args) = 500
→ input_list.append(function_call_output, call_id) → responses.create → output_text

MCP öncesi/sonrası:

Önce:   App1 ─┬─ GitHub        (3 uygulama × 5 araç = 15 entegrasyon)
        App2 ─┼─ Slack ...
        App3 ─┘
Sonra:  App1/App2/App3 → [ MCP katmanı ] → GitHub / Slack / PostgreSQL / Weather API / Stripe

MCP çalışma adımları:

Host → MCP Client oluşturur → Server'a bağlanır → yetenekleri keşfeder
→ tools/list → Server araç listesini döndürür → LLM uygun aracı seçer
→ Client araç çağrısını gönderir → Server çalıştırır
→ Sonuç Client üzerinden Host'a → LLM nihai cevabı üretir

Dersteki pratik zincir:

03-server.py (MCPServer + tool/resource/prompt)

Kod / uygulama

1) Fonksiyon ve tip ipuçları

def add(a: int, b: int) -> int:
    """İki tam sayıyı toplar."""
    return a + b
  • a: int, b: int, -> int → type hint; model/agent'ı doğru parametre tipine yönlendirir.
  • Docstring → aracın açıklaması; model aracı kullanıp kullanmayacağına buna bakarak karar verir.

2) Aracı modele tanıtmak

tools = [{
    "type": "function",
    "name": "add",
    "description": "İki tam sayıyı toplar ve sonucu döndürür.",
    "parameters": {
        "type": "object",
        "properties": {
            "a": {"type": "integer", "description": "Toplanacak ilk sayı"},
            "b": {"type": "integer", "description": "Toplanacak ikinci sayı"}
        },
        "required": ["a", "b"],
        "additionalProperties": False
    },
    "strict": True
}]
  • name / description → modelin araç seçiminde baktığı alanlar (çok dikkatli yazılmalı).
  • parameters → JSON Schema; her parametrenin tipi ve açıklaması.
  • required → zorunlu parametreler.
  • additionalProperties: False → tanımsız ekstra parametre olmasın.
  • strict: True → model şemanın dışına çıkıp parametre "uydurmasın".

3) Konuşma geçmişi olarak liste

input_list = [{"role": "user", "content": "125 ile 375'i topla."}]
  • Liste, çünkü geçmiş büyüyecek: kullanıcı → modelin function call'u → araç çıktısı → … Model kimin ne dediğini bu sırayla takip eder.

4) İlk çağrı

response = client.responses.create(model="gpt-6-luna", input=input_list, tools=tools)
print(response.output)
  • Responses API; tools ile model "bunları kullanabilirsin" bilgisini alır.
  • Çıktıda type="function_call", name, arguments, call_id, status görülür.

5) Function call'u ayıklamak

input_list += response.output
tool_call = next(item for item in response.output if item.type == "function_call")
arguments = json.loads(tool_call.arguments)
  • += → modelin çıktısı geçmişe eklenir (bağlam genişler).
  • next(...) → tipi function_call olan ilk öğe; çok araçlı senaryoda daha anlamlı.
  • json.loads → argümanlar JSON metni olarak gelir, sözlüğe çevrilir.

6) Uygulama fonksiyonu çalıştırır ve sonucu geri verir

result = add(**arguments)
input_list.append({
    "type": "function_call_output",
    "call_id": tool_call.call_id,
    "output": str(result)
})
  • **arguments → sözlüğü anahtar–değer parametreleri olarak açar.
  • call_id → bu çıktının hangi çağrıya ait olduğunu eşler.
  • str(result) → çıktı metin olarak gönderilir.

7) Son cevap

final_response = client.responses.create(model="gpt-6-luna", input=input_list, tools=tools)
print(final_response.output_text)
  • tools yine verilir; model sonuca bakıp aracı tekrar çağırmak isteyebilir.

8) Minimal MCP sunucusu (02-server-demo.py)

from mcp.server import MCPServer

mcp = MCPServer("Bootcamp MCP Server")

@mcp.tool()
def add(a: int, b: int) -> int:
    """İki tam sayıyı toplar."""
    return a + b

if __name__ == "__main__":
    mcp.run(transport="stdio")
  • MCPServer("…") → sunucu örneği (adı istemcide görünür).
  • @mcp.tool() → dekoratör, sıradan fonksiyonu MCP aracına çevirir; şema type hint + docstring'den üretilir (Not: function calling'deki elle yazılan tools sözlüğüne gerek kalmıyor).
  • if __name__ == "__main__": → dosya doğrudan çalıştırılınca sunucu başlar.
  • transport="stdio" → iletişim standart girdi/çıktı ile.

9) Tool + Resource + Prompt (03-server.py, ilgili kısımlar)

@mcp.tool()
def joke(topic: str | None = None) -> str:
    """İsteğe bağlı bir konuya göre kısa bir şaka döndürür."""
    return f"{topic} hakkında bir fıkra"

@mcp.resource("course://mcp")
def course_info() -> str:
    """MCP dersi hakkında kısa bilgi verir."""
    return ("Bu kaynak AI Engineering Bootcamp içindeki "
            "Model Context Protocol dersine aittir.")

@mcp.prompt()
def explain_mcp(level: str = "başlangıç") -> str:
    """MCP konusunu belirtilen seviyeye göre açıklayan prompt oluşturur."""
    return (f"Model Context Protocol konusunu {level} seviyesindeki "
            "bir öğrenciye sade örneklerle açıkla.")
  • str | None = None → isteğe bağlı parametre.
  • @mcp.resource("course://mcp") → URI ile adreslenen salt bilgi kaynağı; modele ek bağlam.
  • @mcp.prompt() → parametreli şablon; level boşsa varsayılan "başlangıç".

11) VS Code yapılandırması (.vscode/mcp.json)

{
  "servers": {
    "ai-engineering-mcp": {
      "type": "stdio",
      "command": "uv",
      "args": ["run", "mcp", "run", "${workspaceFolder}/03-server.py"],
      "cwd": "${workspaceFolder}"
    }
  }
}
  • servers.<ad> → VS Code'da listelenecek sunucu adı.
  • type: stdio → VS Code sunucuyu alt süreç olarak başlatıp stdin/stdout ile konuşur.
  • command + args → uv run mcp run <dosya> çalıştırılır; dosya adı gerçek adla birebir aynı olmalı.
  • ${workspaceFolder} → açık çalışma klasörü; cwd çalışma dizini.

Hocanın vurguları & pratik kurallar

  • Araç tasarlarken fonksiyon adı, açıklama (docstring/description) ve parametre açıklamaları en kritik kısım; model seçimi bunlara bakarak yapıyor.
  • Type hint mutlaka kullanın; uygulama daha doğru çalışıyor.
  • Sadece gerekli araçları bağlayın. Fazla araç = daha yavaş cevap, model kapasitesinin zorlanması.
  • Aracı model çalıştırmaz, uygulama çalıştırır.
  • MCP modeli zekileştirmez; standart bağlantı katmanıdır.
  • Sunucu yazarken .py dosyası kullanın (notebook sadece anlatım/deneme için).
  • Dosya adlarını sıra numarasıyla başlatın (01-…, 02-…) — tekrar ederken kolaylık.
  • Sunucu koduna yeni araç ekledikten sonra sunucuyu yeniden başlatın ve istemcide yeniden bağlanın.
  • Sohbette aracın kullanılmasını garantilemek için istekte araç/sunucu adını açıkça yazın; aksi halde model bazen kendi cevap verir.
  • Eski projelerin .venv klasörünü silerek disk alanı açın.
  • Hata çözümünde Claude/Gemini'ye sormak çoğu zaman işe yarıyor.
  • Yeni yaklaşımları (token tasarrufu sağlayan araç seçimi yöntemleri, yeni formatlar) takip edin.
  • Kariyer: Alan uzmanlığını (ör. uydu/radar görüntü analizi) yapay zekâ ile birleştirmek büyük fırsat; açıklanabilir yapay zekâ (XAI) önemli bir alan; model kıyaslarında bağımsız kullanıcı oylamalı platformlar (Arena) daha anlamlı.
  • Donanım: ~27B bir modeli yerelde çalıştırmak için ~24 GB VRAM; 16 GB'ta yavaş. 7/24 otomasyon için 32 GB Mac mini veya ucuz bir VPS.

Kendini test et

  1. Function calling'de aracı kim çalıştırır: model mi, uygulama mı? Modelin görevi nedir?
Cevap

Aracı uygulama çalıştırır. Model yalnızca hangi aracın, hangi parametrelerle çağrılacağına karar verir ve bunu bir function_call olarak döndürür.

  1. tools tanımında strict: True ve additionalProperties: False ne işe yarar?
Cevap

Modelin şemanın dışına çıkmasını engeller: tanımsız ekstra parametre eklenmez, model parametre uydurmaz; sadece tanımlı a ve b kullanılır.

  1. input_list neden bir liste? Bu derste sırasıyla hangi öğeler eklendi?
Cevap

Konuşma geçmişini tutmak için. Sıra: kullanıcı mesajı (role: user) → modelin çıktısı (function_call) → araç sonucu (function_call_output, call_id, output).

  1. call_id neden gönderilir?
Cevap

Araç çıktısının modelin hangi çağrısına ait olduğunu eşleştirmek için; birden fazla çağrı olduğunda model hangi sonucun hangi isteğe karşılık geldiğini bilir.

  1. 4 AI uygulaması ve 6 araç varsa doğrudan entegrasyonla kaç entegrasyon gerekir? MCP bunu nasıl değiştirir?
Cevap

4 × 6 = 24 entegrasyon. MCP ile her araç bir kez MCP sunucusu olarak yazılır, her uygulama MCP standardıyla bağlanır; bağlantı sayısı çarpım yerine toplam gibi büyür (M + N).

  1. MCP'nin üç temel yapısı nedir, her birini birer cümleyle açıklayın.
Cevap

Tools: çağrılabilir araçlar/fonksiyonlar. Resources: modele ek bilgi sağlayan, URI ile adreslenen kaynaklar. Prompts: parametre alabilen hazır prompt şablonları.

  1. Host, Client ve Server'ı tanımlayın; VS Code bu derste hangi roldeydi?
Cevap

Host: LLM'i çalıştıran ve kullanıcıyla konuşan AI uygulaması. Client: host içinde bir sunucuyla bağlantıyı yöneten bileşen. Server: araç/kaynak/şablonları standart biçimde sunan program. VS Code host rolündeydi.

  1. @mcp.tool() dekoratörü ne yapar ve function calling'deki tools sözlüğüne göre farkı nedir?
Cevap

Sıradan bir Python fonksiyonunu MCP aracı olarak kaydeder. Aracın adı, açıklaması ve parametre şeması fonksiyon adı, docstring ve type hint'lerden alınır; JSON şemasını elle yazmaya gerek kalmaz.

  1. uv run mcp dev 02-server-demo.py çalıştırınca npx hatası alıyorsunuz. Sebep ve çözüm?
Cevap

MCP Inspector Node.js tabanlı ve Node.js kurulu değil. Node.js kurulur, node --version ile doğrulanır, terminal/VS Code yeniden açılır.

  1. VS Code mcp.json'daki sunucuyu listelemiyor. İlk kontrol edeceğiniz şey nedir?
Cevap

Dosyanın .vscode/mcp.json konumunda olup olmadığı (proje kökünde değil). Ardından args içindeki dosya adının doğruluğu.
