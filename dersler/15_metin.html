HuggingFace nedir? (≈00:11–00:13)

  • Açık kaynak modellerle çalışmak için en çok kullanılan iki araç Ollama ve HuggingFace. Ollama ChatGPT'den sonra çıktı; HuggingFace'in geçmişi daha eski.
  • HuggingFace 2017'de bir chatbot şirketi olarak kuruldu. Transformer mimarisinden sonra birçok model geliştirildi; bu modellerle çalışmak için transformers kütüphanesini yazdılar. Bu kütüphaneyle büyük dil modelleri çok kolay çalıştırılabiliyor.
  • HuggingFace aslında uçtan uca makine öğrenmesi analizleri için bir framework. Hiyerarşi: modül → kütüphane → framework. Framework birden fazla kütüphaneyi barındırır. İçinde bilgisayarlı görü (computer vision), NLP, ses vb. için ayrı kütüphaneler var.

İlk pipeline: metin sınıflandırma / duygu analizi (≈00:53–00:58)

HuggingFace'in en güzel tarafı: birkaç satır kodla büyük modellerle çalışabilmek. Bunun için pipeline kullanılır (başka yöntemler de var).

Model nasıl seçilir? huggingface.co → Models → Tasks altında NLP → Text Classification. Trend olan / en çok beğenilen modellere bakılır; isterseniz parametre filtresiyle küçük modelleri seçersiniz. Model adının yanındaki kopyala butonuyla adı alıp koda yapıştırırsınız. Hoca küçük bir model seçti: DistilBERT.

BERT / DistilBERT hatırlatması: Transformer mimarisi iki parçadan oluşur: encoder ve decoder. Decoder'dan GPT geliştirildi (metin üretmek için). Encoder kısmı metin sınıflandırma gibi işler için kullanılıyor; Google 2018'de buradan BERT'i geliştirdi. DistilBERT, BERT'in daha küçük bir versiyonu.

Not: Hoca DistilBERT'i "quantize edilmiş hali gibi düşünebilirsiniz" diye anlattı; teknik olarak DistilBERT bilgi damıtma (knowledge distillation) ile küçültülmüş bir modeldir, quantization değil.

from transformers import pipeline

classifier = pipeline(
    'text-classification',
    model="distilbert/distilbert-base-uncased-finetuned-sst-2-english"
)

classifier("I really enjoyed this movie.")
  • model parametresi verilmezse o görev için ön tanımlı (default) model iner.
  • pipeline'ın güzel tarafı: hem modeli hem de o modelin tokenizer'ını indirir. Her modelin kendi tokenizer'ı vardır ve metin o tokenizer'a göre token'lara ayrılmalıdır.
  • Çıktı: POSITIVE, skor ≈ 0.99. Öğrencilerde de aynı sonuç çıktı.

(Mola sonrası) Agent'larla bilimsel araştırma — hocanın deneyimi (≈01:18–01:26)

Hoca, bir yurt dışı konferansı için genetik varyantlar üzerine yaptığı bir çalışmayı anlattı. Bunu bir agent aracıyla (transkriptte "Hermes" gibi okunuyor [belirsiz]) ve bir Qwen modeliyle [belirsiz: model adı/sürümü] yaptırdı:

  • Agent gece boyunca çalıştı: veriyi indirdi, kodları kendisi yazdı, testleri ve analizleri yaptı, okunacak makaleleri indirdi, sonuçları raporladı; kendi metodoloji eksiğini bulup kapattı.
  • Denetleyici agent: Bir agent analizi yapıyor, başka bir agent bunu kontrol ediyor. İki farklı model (bir Qwen, bir OpenAI modeli) kullanıp kararlarını karşılaştırmayı planlıyor.
  • Hoca'nın yorumu: "Herkes uygulama yapıyor ama herkes yeni bir şey bulamıyor." Agent'ları iyi yönlendirerek makale yazmak / araştırma yapmak daha değerli olabilir. Eskiden bir çalışma için biri kod, biri alan bilgisi olmak üzere iki-üç kişi gerekirdi; artık tek kişi birçok araştırma yapabilir.
  • Ama yazarken anlamak şart: agent'tan ne yaptığını adım adım ve teknik olarak açıklamasını isteyin; kendi ifadelerinizle yazmak daha iyidir.
  • Bir öğrencinin önerisi (hoca beğendi): Modelleri çapraz kontrol ettirmek — örn. Codex bir şey yazıyor, ChatGPT'ye kontrol ettiriyorsun; ayrıca bir "karar mercii" ajan belirleyip ona rol vermek (araştırmacı gözüyle, yayıncı gözüyle bak). Tartışmaları okumak da öğretici oluyor.
  • Tıp alanında bu yaklaşımın önemi: yanlış teşhis örneği verildi; bir AI teşhis koyarken diğerinin kontrol etmesi bu riski azaltabilir.

from skimage.color import rgb2gray

def transform_image(img):
    return rgb2gray(img)

import gradio as gr

demo = gr.Interface(
    fn=transform_image,
    inputs=gr.Image(),
    outputs="image"
)
demo.launch()
  • fn: çalışacak fonksiyon; inputs: girdi bileşeni (resim); outputs: çıktı tipi (resim).

SQL Editor'da tablo oluşturma ve RLS (≈02:52–02:58)

SQL Editor'da hocanın paylaştığı sorgu çalıştırıldı (sağ üstte Run). Sorgunun yaptıkları:

  1. public şeması içinde students tablosu oluşturur.
  2. id: her öğrenciye otomatik artan bir kimlik; aynı zamanda primary key.
  3. name: metin sütunu.
  4. course: metin, boş olamaz (not null).
  5. INSERT ile örnek (dummy) veriler: [belirsiz: ilk isim, "Ayşe" olabilir] → Python, Mehmet → Yapay Zekâ, Zeynep → Veri Bilimi.
  6. Satır düzeyi güvenlik (Row Level Security, RLS) açılır — herkes tabloya erişemesin diye.
  7. Bir policy ile erişim sadece service_role (backend rolü) için verilir; bu rol dışındakiler satırları göremez.

Not: SQL kodu ders dosyalarında yok; yukarıdaki maddeler anlatımdan çıkarılmıştır. Yaklaşık karşılığı: sql create table public.students ( id bigint generated always as identity primary key, name text, course text not null ); insert into public.students (name, course) values ('Ayşe', 'Python'), ('Mehmet', 'Yapay Zeka'), ('Zeynep', 'Veri Bilimi'); alter table public.students enable row level security; create policy "service role access" on public.students for all to service_role using (true) with check (true);

Çalıştırdıktan sonra Table Editor → students'ta tablo ve veriler görünür; "artık bulutta tablomuz var."

Sorunlar: Sohbete yapıştırılan kodda görünmez karakterler/boşluklar hata verdi ("syntax error") → hoca bozuk karakterleri sildi; bazı öğrenciler kodu Claude'a düzelttirip yapıştırdı. Sorguyu iki kez çalıştırınca da "zaten var" hatası alınabilir.

Python'dan Supabase bağlantı testi (≈02:58–03:06)

Yeni dosya: supabase.py (ders dosyalarında 2_test_supabase.py).

import os

from dotenv import load_dotenv
from supabase import create_client

load_dotenv()

supabase = create_client(
    os.environ["SUPABASE_URL"],
    os.environ["SUPABASE_SECRET_KEY"],
)

response = (
    supabase.table("students")
    .select("id, name, course")
    .order("id")
    .execute()
)

# print("✅ Bağlantı ve tablo okuma başarılı!")

for student in response.data:
    print(f"{student['id']} | {student['name']} | {student['course']}")
  • load_dotenv(): .env içindeki ortam değişkenlerini çalışma ortamına alır.
  • create_client(...): URL ve secret key ile Supabase istemcisi oluşturur.
  • students tablosundan id, name, course seçilir, id'ye göre sıralanır, execute() ile çalıştırılır.
  • Önce sadece "Bağlantı ve tablo okuma başarılı" yazdırıldı; sonra bu satır yoruma alınıp satırlar ekrana basıldı: 1 | <isim> | Python, 2 | Mehmet | Yapay Zeka … biçiminde.
uv run supabase.py

Sonuç: Lokal bilgisayardan buluttaki Supabase tablosuna bağlanıp verileri çekebildik. Bir sonraki adım: metni alıp token'lara, token'ları vektörlere çevirip Supabase'e kaydetmek ve veritabanında en yakın vektörleri bulmak (vektör araması).
