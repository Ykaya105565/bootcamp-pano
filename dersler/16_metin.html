Vektör veritabanı şeması: scripts/setup_database.py (≈01:21–01:33)

Geçen ders tablo Supabase arayüzünden/SQL Editor'dan oluşturulmuştu; bu sefer kodla oluşturuluyor. Proje kökünde scripts klasörü açılıp içine setup_database.py yazıldı.

import os
import psycopg
from dotenv import load_dotenv

load_dotenv()
database_url = os.environ["DATABASE_URL"]

with psycopg.connect(database_url) as connection:
    with connection.cursor() as cursor:
        cursor.execute("SET LOCAL search_path = public, extensions;")
        cursor.execute(
            """
            CREATE EXTENSION IF NOT EXISTS vector;
            """
        )

        # Belgelerin saklanacağı tablo
        cursor.execute(
            """
            CREATE TABLE IF NOT EXISTS documents (
                id BIGSERIAL PRIMARY KEY,
                content TEXT NOT NULL,
                metadata JSONB NOT NULL,
                embedding VECTOR(1536) NOT NULL,
                created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
            );
            """
        )
        # Vektör aramalarını hızlandıran indeks
        cursor.execute(
            """
            CREATE INDEX IF NOT EXISTS documents_embedding_hnsw_idx
            ON documents
            USING hnsw (embedding vector_cosine_ops);
            """
        )

        # Benzer belgeleri getiren fonksiyon
        cursor.execute(
            """
            CREATE OR REPLACE FUNCTION match_documents(
                query_embedding VECTOR(1536),
                match_count INT DEFAULT NULL,
                filter JSONB DEFAULT '{}'
            )
            RETURNS TABLE (
                id BIGINT,
                content TEXT,
                metadata JSONB,
                embedding JSONB,
                similarity FLOAT
            )
            LANGUAGE sql
            SET search_path = public, extensions
            AS $$
                SELECT
                    d.id,
                    d.content,
                    d.metadata,
                    (d.embedding::TEXT)::JSONB AS embedding,
                    1 - (d.embedding <=> query_embedding) AS similarity
                FROM documents AS d
                WHERE d.metadata @> filter
                ORDER BY d.embedding <=> query_embedding
                LIMIT match_count;
            $$;
            """
        )
        # Row Level Security
        cursor.execute(
            """
            ALTER TABLE documents ENABLE ROW LEVEL SECURITY;
            """
        )

print("✅ Supabase vector store şeması hazır.")

Hocanın açıklaması, adım adım:

  1. İmportlar: os (ortam değişkenleri/API anahtarları için), psycopg (PostgreSQL bağlantısı), load_dotenv (.env'deki anahtarları almak için).
  2. DATABASE_URL ortam değişkeni alınır; veritabanına bununla bağlanılır. Bağlantı ve cursor with ile açılır.
  3. SET LOCAL search_path = public, extensions → Supabase içinde public (ve eklentilerin bulunduğu extensions) şemasında çalışacağımızı söyler.
  4. CREATE EXTENSION IF NOT EXISTS vector → PostgreSQL klasik bir veritabanı; onu vektör veritabanına çevirmek için eklenti (extension) kullanıyoruz. vector eklentisi yoksa oluşturulur. Artık vektörler bu veritabanında saklanabilir.
  5. documents tablosu (yoksa oluşturulur): - id → primary key, her satırı tanımlayan benzersiz (unique) değer. - content → doküman metni. - metadata → JSON biçiminde metadata. - embedding → embedding'leri saklamak için vektör sütunu. - created_at → oluşturulma tarihi. - NOT NULL → bu alanlar boş geçilemez.
  6. HNSW indeksi → Vektör aramalarını hızlandırır. Normal indekslerle vektörlerde hızlı arama yapılamaz; HNSW indeksiyle yapılabilir.
  7. match_documents fonksiyonu (vektör araması için): - Parametreler: query_embedding (sorgunun embedding'i — benzerlik araması bununla yapılır), match_count (kaç benzer doküman isteniyor), filter (metadata filtresi; RAG derslerindeki gibi örneğin sadece 2026 yılının verilerini filtrelemek için). - Döndürdükleri: id, content, metadata, embedding, similarity. - LANGUAGE sql → fonksiyonun SQL diliyle yazıldığını söyler; fonksiyonun gövdesi çift dolar ($$) sembolleri arasına yazılır. - Sorgu: documents tablosundan (d) sütunlar seçilir; filtre varsa uygulanır (metadata @> filter); <=> sembolü kosinüs benzerliği/uzaklığı ile sorgu embedding'i veritabanındaki vektörlerle karşılaştırır, en benzerler sıralanır ve match_count kadar döndürülür.
  8. RLS: PostgreSQL'in özelliği olan satır düzeyi güvenlik (Row Level Security) açılır; satır bazında kullanıcı yetkileri belirlenebilir. Şimdilik sadece açılıyor.
  9. Son olarak şemanın oluştuğunu göstermek için ekrana mesaj yazılır.

from langchain_core.tools import tool
from .vector_store import vector_store
from langchain.agents import create_agent

@tool
def search_course_notes(query: str) -> str:
    """AI Engineering Bootcamp ders notlarında anlamsal arama yapar."""

    documents = vector_store.similarity_search(
        query,
        k=3,
    )

    if not documents:
        return "Ders notlarında ilgili bilgi bulunamadı."

    return "\n\n".join(
        document.page_content
        for document in documents
    )

agent = create_agent(
    model="openai:gpt-4.1-mini",
    tools=[search_course_notes],
    system_prompt=(
        "Sen AI Engineering Bootcamp ders asistanısın. "
        "Ders içeriğiyle ilgili sorularda önce "
        "search_course_notes aracını kullan. "
        "Bulamadığın bilgiyi bulmuş gibi söyleme."
    ),
)

import streamlit as st
from langgraph_sdk import get_sync_client


client = get_sync_client(
    url="http://127.0.0.1:2024"
)

st.title("AI Engineering Bootcamp Assistant")


# LangGraph thread
if "thread_id" not in st.session_state:
    thread = client.threads.create()
    st.session_state.thread_id = thread["thread_id"]


# Streamlit chat history
if "messages" not in st.session_state:
    st.session_state.messages = []


# Eski mesajları göster
for message in st.session_state.messages:
    with st.chat_message(message["role"]):
        st.write(message["content"])


# Kullanıcı mesajı
question = st.chat_input(
    "Ders notları hakkında bir soru sor..."
)


if question:
    st.session_state.messages.append(
        {
            "role": "user",
            "content": question,
        }
    )

    with st.chat_message("user"):
        st.write(question)

    final_answer = ""

    # Agent Server'a gönder
    for event in client.runs.stream(
        # Çalışacağımız konuşma 
        st.session_state.thread_id,
        # langgraph.json içindeki graph adımız.
        "agent",
        # Agent gidecek input
        input={
            "messages": [
                {
                    "role": "user",
                    "content": question,
                }
            ]
        },
        stream_mode="values",
    ):

        if event.event == "values":
            messages = event.data.get(
                "messages",
                []
            )
            if messages:
                last_message = messages[-1]
                if isinstance(last_message, dict):
                    final_answer = last_message.get(
                        "content",
                        ""
                    )


    # Agent cevabı
    if final_answer:
        st.session_state.messages.append(
            {
                "role": "assistant",
                "content": final_answer,
            }
        )

        with st.chat_message("assistant"):
            st.write(final_answer)

Bunu yapmazsak her seferinde farklı bir thread ID oluşur; yani her mesajda yeni bir sohbet açılmış gibi olur, geçmiş konuşmalar gider. 4.
