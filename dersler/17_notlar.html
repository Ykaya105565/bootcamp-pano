16. dersten kısa hatırlatma

Supabase/pgvector'lü bir RAG agent LangGraph yerel sunucusunda yayınlanmış, LangSmith ile izlenmiş, Streamlit arayüzüyle denenmişti. Ders sonunda son dersin HuggingFace ile fine-tuning (transformers, peft, datasets) olacağı ve bitirme projelerinin son derste sunulabileceği söylenmişti.

Ana kavramlar

  • Fine-tuning (ince ayar): Önceden eğitilmiş bir modelin parametrelerini kendi verimizle güncellemek. Neden önemli: Modelin davranışını/formatını/alan dilini kalıcı olarak değiştirir; çok veride RAG'in token maliyetinden kurtarır.
  • Parametrik vs parametrik olmayan: Fine-tuning parametrik (ağırlıklar değişir); RAG parametrik değil (ağırlıklar sabit, bilgi bağlamla gelir).
  • RAG mı, fine-tuning mi? (hocanın kuralı): Sınırlı sayıda kaliteli ve sık güncellenen veri, güncel bilgi ihtiyacı → RAG. Çok fazla veri, "bir kez eğit, sonra kullan" → fine-tuning. Hibrit de olur: alana göre fine-tune + üstüne RAG.
  • Full fine-tuning: Tüm parametreleri eğitmek. Pahalı, uzun, uzmanlık ister.
  • LoRA (Low-Rank Adaptation): Ağırlıklar dondurulur; yanına küçük eğitilebilir matrisler (adaptör: lora_A, lora_B) eklenir; yalnızca bunlar eğitilir, sonra temel ağırlıklarla birleştirilir. Neden önemli: Az GPU, az disk (adaptör ≈ onlarca MB).
  • Quantization: Parametrelerin bit sayısını düşürmek (float32/16 → 4 bit). Bellek ihtiyacını büyük ölçüde azaltır.
  • QLoRA: 4-bit quantize edilmiş temel model + LoRA adaptörleri. Neden burada: Düz LoRA bu model için ≈50–60 GB GPU belleği isterdi.
  • NF4 / double quant / compute dtype: bitsandbytes ayarları: 4-bit "normal float" tipi, quantization sabitlerinin de quantize edilmesi, hesaplamaların bfloat16 ile yapılması.
  • Pre-training vs post-training: Ön eğitimde model bir sonraki token'ı tahmin etmeyi öğrenir (soruya cevap vermeyi bilmez); son eğitimde talimat–cevap örnekleriyle cevap vermeyi öğrenir.
  • SFT (Supervised Fine-Tuning): Girdi–beklenen çıktı çiftleriyle denetimli eğitim; TRL'nin SFTTrainer/SFTConfig sınıfları.
  • Chat template / messages formatı: Her modelin kendi girdi formatı vardır; veriyi {"role": "user"/"assistant", "content": ...} listesine çevirmek gerekir.
  • rank r, lora_alpha, lora_dropout, target_modules: Adaptör boyutu (büyük r → daha çok parametre), adaptör katkısının ölçeği, ezberlemeyi önleyen dropout, adaptörün takılacağı katmanlar.
  • Loss, gradyan, backpropagation: Tahmin–gerçek farkı (kayıp) geriye dağıtılırken gradyanlar hesaplanır, katsayılar güncellenir.
  • Gradient accumulation: Gradyanları birkaç adım biriktirip sonra güncellemek; küçük batch'le büyük batch etkisi.
  • Gradient checkpointing: Not: Bellek tasarrufu; aktivasyonlar yeniden hesaplanır (hoca "kontrol noktası" diye anlattı).
  • KV cache (use_cache): Üretimde önceki token hesaplarını saklar; eğitimde kapatılır, çıkarımda açılır.
  • MoE (Mixture of Experts): Router'ın yalnızca ilgili uzmanları çalıştırdığı LLM mimarisi; LoRA buna da uygulanabilir.
  • HuggingFace Hub: Adaptörün yüklendiği (push_to_hub) ve geri çekildiği (PeftModel.from_pretrained) depo.
  • Agentic RAG (öğrenci projesi): Router + tool'lar + (isteğe bağlı) multi-agent ile RAG; kararlar evaluation ile verildi.
  • Agent tasarım kalıpları: Router, reflection, ReAct, planner, RAG, guardrails. Framework'ler değişir, kalıplar kalır.

Akış / mimari

RAG mı fine-tuning mi? (karar şeması)

Özel/güncel veri ihtiyacı
 ├─ veri az + sık güncelleniyor + güncel bilgi lazım → RAG (embedding → vektör DB)
 ├─ veri çok + bir kez eğitip kullanılacak            → fine-tuning (LoRA/QLoRA)
 └─ ikisi birden                                      → hibrit: alana fine-tune + üstüne RAG
Güncel dış bilgi → tool / MCP

Full fine-tuning vs LoRA vs QLoRA

Full FT : girdi → [tüm ağırlıklar eğitilir] → yeni model           (pahalı, uzun)
LoRA    : girdi → [ağırlıklar donuk] + [A·B adaptör eğitilir] → birleştir
QLoRA   : girdi → [ağırlıklar donuk + 4-bit NF4] + [A·B adaptör, bf16] → birleştir

Uygulama akışı (QLoRA.ipynb)

pip install → AutoTokenizer (Qwen/Qwen3-8B) → BitsAndBytesConfig (4-bit nf4)
 → AutoModelForCausalLM (4-bit, device_map="auto")
 → load_dataset(dolly-15k): train[0:800], train[800:1000]
 → generate_prompt + map  → "messages" (user / assistant)
 → prepare_model_for_kbit_training → LoraConfig (r=8, alpha=16, all-linear)
 → notebook_login (HF_TOKEN) → SFTConfig (20 adım) → use_cache=False
 → SFTTrainer(... peft_config) → print_trainable_parameters (%0,27) → train()
 → push_to_hub("qwen3-8b-dolly-qlora")  [adaptör 43,7 MB]
 ── (ayrı oturumda da yapılabilir) ──
 → PeftConfig (base_model_name_or_path) → temel model 4-bit → PeftModel.from_pretrained
 → eval() + use_cache=True → apply_chat_template → generate (no_grad) → decode

Öğrenci projesi (agentic RAG) mimarisi — özet

Soru → Router ─ kapsam dışı / tavsiye → reddet
          └─ diğer → tek agent (varsayılan) | supervisor → [finansal veri, dipnot] → sentez
Tool'lar: financials CSV (hesap kodla) · dipnot RAG (Chroma + BM25) · fiyat (Yahoo Finance) · ...
Kontrol: sayı / dönem / birim / tavsiye dili → kaynaklı cevap · Streamlit + MCP sunucusu

2) Tokenizer ve 4-bit model

base_model = "Qwen/Qwen3-8B"
tokenizer = AutoTokenizer.from_pretrained(base_model, padding_side = "right",)

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16
    )

model = AutoModelForCausalLM.from_pretrained(
    base_model, quantization_config=bnb_config, device_map="auto",)
  • padding_side="right": Eğitimde dolgu token'ları sağa eklenir (causal LM eğitiminde yaygın tercih).
  • load_in_4bit=True: Ağırlıklar 4 bit'e indirilir → QLoRA'nın "Q"su.
  • bnb_4bit_quant_type="nf4": Ağırlık dağılımına uygun 4-bit "normal float" tipi.
  • bnb_4bit_use_double_quant=True: Quantization sabitleri de quantize edilir → ek bellek tasarrufu.
  • bnb_4bit_compute_dtype=torch.bfloat16: Depolama 4 bit, hesaplama bf16. T4'te bf16 yok → torch.float16 (Not).
  • AutoModelForCausalLM: Token üreten (causal) model sınıfı; device_map="auto" modeli GPU'ya yerleştirir.

3) Veri seti ve sohbet formatı

dataset_name = "databricks/databricks-dolly-15k"
train_dataset = load_dataset(dataset_name, split="train[0:800]")
eval_dataset = load_dataset(dataset_name, split="train[800:1000]")

def generate_prompt(sample):
    user_content = sample["instruction"]
    if sample["context"]:
        user_content += f"\n\nContext:\n{sample['context']}"
    return {"messages": [
        {"role": "user", "content": user_content},
        {"role": "assistant", "content": sample["response"]}]}

generated_train_dataset = train_dataset.map(generate_prompt)
generated_val_dataset = eval_dataset.map(generate_prompt)
  • split="train[0:800]": Dolly'nin tek bölümü olan train'den dilimle eğitim (800) ve değerlendirme (200) kümesi oluşturulur; iki küme çakışmaz.
  • if sample["context"]: Bağlam boş değilse talimatın altına "Context:" ile eklenir (bağlam her örnekte yok).
  • messages listesi: Modelin sohbet şablonunun beklediği role/content yapısı; assistant içeriği öğrenilecek cevaptır.
  • map: Fonksiyonu her örneğe uygular, yeni messages sütununu ekler.
  • Kategori dağılımı (800 örnek): open_qa 202, general_qa 132, classification 111, brainstorming 95, closed_qa 90, information_extraction 68, summarization 63, creative_writing 39.

4) PEFT hazırlığı ve LoraConfig

model = prepare_model_for_kbit_training(model)

lora_config = LoraConfig(r=8, lora_alpha=16, target_modules="all-linear",
    bias="none", lora_dropout=0.05, task_type="CAUSAL_LM",)
  • prepare_model_for_kbit_training: 4-bit modeli eğitime hazırlar (temel ağırlıkları dondurur, kararlılık için bazı katmanları uygun tipe çevirir, gradient checkpointing'e hazırlar).
  • r=8: Adaptör matrislerinin rank'ı; lora_A 4096→8, lora_B 8→4096 (eval() çıktısında görüldü).
  • lora_alpha=16: Adaptör katkısının ölçeği (Not: etkin ölçek genellikle alpha/r = 2).
  • target_modules="all-linear": Tüm linear katmanlara (q/k/v/o projeksiyonları, MLP) adaptör.
  • bias="none", lora_dropout=0.05, task_type="CAUSAL_LM": bias eğitilmez; %5 dropout ezberlemeye karşı; görev: token üretimi.

5) Hub girişi ve eğitim ayarları

notebook_login()     # HF_TOKEN (yazma yetkili) — değeri asla notebook'a yazılmaz

training_arguments = SFTConfig(output_dir="./results",
    per_device_train_batch_size=1, gradient_accumulation_steps=4,
    gradient_checkpointing=True, learning_rate=2e-4, weight_decay=0.001,
    max_steps=20, logging_steps=5, save_strategy="steps", save_steps=10,
    eval_strategy="steps", eval_steps=10, bf16=True, report_to="none",)
model.config.use_cache = False
  • Etkin batch = 1 × 4 = 4 örnek/adım; 20 adım → ≈80 örnek (epoch 0,1).
  • learning_rate=2e-4: LoRA için tipik görece yüksek öğrenme oranı (yalnızca küçük adaptörler eğitiliyor).
  • weight_decay=0.001: Ağırlıkları küçük tutarak aşırı uyumu azaltan düzenlileştirme.
  • save_steps=10 / eval_steps=10: 10 adımda bir checkpoint (./results) ve doğrulama kaybı.
  • bf16=True: A100'de çalışır; T4'te bf16=False, fp16=True (Not).
  • report_to="none": W&B vb. izleme aracı kullanılmıyor.
  • use_cache=False: KV cache eğitimde gereksiz, gradient checkpointing ile çakışır.

6) Trainer, eğitim, Hub'a yükleme

trainer = SFTTrainer(model=model, args=training_arguments, processing_class=tokenizer,
    train_dataset=generated_train_dataset, eval_dataset=generated_val_dataset,
    peft_config=lora_config,)
trainer.model.print_trainable_parameters()
# trainable params: 21,823,488 || all params: 8,212,558,848 || trainable%: 0.2657
trainer.train()        # 20 adım, ≈101 sn, training_loss ≈ 2,10
trainer.model.push_to_hub("qwen3-8b-dolly-qlora")   # adapter_model.safetensors 43,7 MB
  • processing_class=tokenizer: TRL, messages'i tokenizer'ın chat şablonuyla metne/token'a çevirir, etiketleri oluşturur, uzunları kırpar.
  • peft_config=lora_config: Adaptörleri trainer takar; ayrıca get_peft_model çağırmaya gerek kalmaz.
  • %0,27: 8,2 milyar parametrenin yalnızca 21,8 milyonu eğitiliyor.
  • push_to_hub: Yalnızca adaptör ağırlıkları ve adapter_config.json yüklenir, 8B modelin kendisi değil.

7) Adaptörü geri yükleme ve çıkarım

peft_model_id = "Tirendaz/qwen3-8b-dolly-qlora"
config = PeftConfig.from_pretrained(peft_model_id)      # base: Qwen/Qwen3-8B
base_model = AutoModelForCausalLM.from_pretrained(config.base_model_name_or_path,
    quantization_config=bnb_config, device_map="auto",)
tokenizer = AutoTokenizer.from_pretrained(config.base_model_name_or_path,)
fine_tuned_model = PeftModel.from_pretrained(base_model, peft_model_id,)
fine_tuned_model.eval(); fine_tuned_model.config.use_cache = True

inputs = tokenizer.apply_chat_template(messages, add_generation_prompt=True,
    tokenize=True, return_dict=True, return_tensors="pt", enable_thinking=False,)
inputs = inputs.to(fine_tuned_model.device)
with torch.no_grad():
    outputs = fine_tuned_model.generate(**inputs, max_new_tokens=100, do_sample=False,)
response = tokenizer.decode(outputs[0, inputs["input_ids"].shape[1]:], skip_special_tokens=True,)
  • PeftConfig.base_model_name_or_path: Adaptör hangi temel modelle eğitildiyse onu söyler; doğru temel modeli yüklemenin güvenli yolu.
  • PeftModel.from_pretrained: Adaptörü temel modelin üstüne takar (kalıcı birleştirme değil).
  • eval(): Dropout vb. eğitim davranışlarını kapatır.
  • add_generation_prompt=True: Şablonun sonuna "şimdi asistan konuşacak" işaretini ekler.
  • enable_thinking=False: Qwen3'ün düşünme (reasoning) modunu kapatır, doğrudan cevap.
  • torch.no_grad(): Çıkarımda gradyan hesaplanmaz → daha az bellek, daha hızlı.
  • do_sample=False: Greedy, deterministik çıktı; max_new_tokens=100: en çok 100 yeni token.
  • outputs[0, inputs["input_ids"].shape[1]:]: Çıktı girdiyi de içerir; girdinin uzunluğu kadar token atlanıp yalnızca yeni üretilenler çözülür.
  • Sonuçlar: Python sorusuna tek cümlelik doğru cevap; "When was Tomoaki Komorida born?" sorusuna "April 17, 1987" (hocanın kontrolüne göre veri setiyle uyuşmadı [belirsiz]).

Hocanın vurguları & pratik kurallar

  • RAG ve fine-tuning rakip değil, araç: Biri diğerinden üstün değil; durumu bilip seçin. Az + sık değişen veri → RAG; çok veri + bir kez eğit → fine-tuning; hibrit mümkün.
  • Çok fazla bağlam modeli şaşırtır: Büyük veriyi RAG ile vermek hem çok token yakar hem modelin "kafasını karıştırabilir".
  • Fine-tuning artık ucuz: LoRA/QLoRA ile tüm modeli eğitmek gerekmiyor; adaptör ≈30–40 MB (uygulamada 43,7 MB).
  • Neden QLoRA: Düz LoRA ≈50–60 GB GPU belleği isterdi.
  • Veri her şeydir: Kaliteli veri → kaliteli model; bugünün açık modelleri zaten çok iyi, fark veriyle yaratılır (Fei-Fei Li / ImageNet örneği).
  • Her modelin girdi şablonu farklı: Veriyi modelin formatına (messages/chat template) çevirin.
  • Hiperparametreler projeye göre: r, gradient accumulation, adım sayısı vb. veriye ve projeye göre ayarlanır; 20 adım yalnızca ders için.
  • Fine-tuning formatı öğretir, bilgiyi değil: "Bu bilgiyi öğretmedik; soruya cevap vermeyi öğrettik." (Komorida örneği.)
  • Modelin eğitildiğini test etmek için ham modele aynı soruyu sorup karşılaştırın (Not: Qwen3-8B zaten sohbet modeli; adaptörsüz/adaptörlü karşılaştırma daha anlamlı).
  • Projelerde ölçün: Öğrenci sunumundaki gibi doğruluk ve gecikmeyi ölçerek karar verin (tek agent %95 / 3,6 sn vs multi-agent %92; critic agent kapatıldı).
  • İzleyin: Token, maliyet, evaluation ve agent'ın izlediği yol (trajectory) için LangSmith gibi araçlar.
  • Mükemmeli beklemeyin: Projeyi açık kaynak yapıp paylaşın, geri bildirimle iterasyonla geliştirin.
  • Tasarım kalıpları kalıcıdır: Router, reflection, ReAct, planner, guardrails; "hangisi en iyi" → projeye göre. Evaluation yükselen bir alan; bilmek işe girişi kolaylaştırır.
  • Kaynaklar: Laurence Moroney (AI and ML for Coders; fine-tuning kitabı [belirsiz]), Manning yayınları, Sebastian Raschka (LLM / reasoning model from scratch), Chip Huyen (güncellenmesi gerekiyor), agent tasarım kalıpları ve evaluation kitapları.

Kendini test et

  1. Hocanın kuralına göre RAG ve fine-tuning hangi durumlarda tercih edilir?
Cevap

Sınırlı sayıda kaliteli ve sık güncellenen veri ile güncel bilgi ihtiyacı varsa RAG (ağırlıklar değişmez, veri vektör DB'de hızla güncellenir). Çok fazla veri varsa ve "bir kez eğitip kullanacağım" deniyorsa fine-tuning. İkisi birlikte (hibrit) de kullanılabilir.

  1. "RAG parametrik değil, fine-tuning parametrik" ne demek?
Cevap

RAG'de modelin ağırlıkları değişmez; bilgi her sorguda bağlam olarak verilir. Fine-tuning'de modelin (ya da adaptörün) parametreleri eğitimle güncellenir; bilgi/davranış ağırlıklara yerleşir.

  1. LoRA, full fine-tuning'den nasıl farklı ve neden daha ucuz?
Cevap

Full fine-tuning tüm ağırlıkları eğitir. LoRA ağırlıkları dondurur, yanına küçük düşük rank'lı matrisler (adaptör) ekleyip yalnızca onları eğitir. Bu derste 8,2 milyar parametrenin yalnızca 21,8 milyonu (%0,27) eğitildi; adaptör 43,7 MB.

  1. QLoRA'daki "Q" neyi ekliyor ve bu derste neden gerekliydi?
Cevap

Quantization: Temel modelin ağırlıkları 4 bit'e (NF4) indirilir, adaptörler bunun üstünde eğitilir. Düz LoRA Qwen3-8B için ≈50–60 GB GPU belleği isterdi; 4-bit ile Colab GPU'suna sığıyor.

  1. generate_prompt fonksiyonu neden yazıldı; context boşsa ne olur?
Cevap

Her modelin kendi girdi şablonu var; Dolly'nin instruction/context/response sütunları sohbet formatına (messages: user + assistant) çevrilmeli ki SFTTrainer modeli doğru şablonla eğitebilsin. Bağlam boşsa yalnızca talimat kullanıcı içeriği olur; doluysa "Context:" başlığıyla eklenir.

  1. per_device_train_batch_size=1, gradient_accumulation_steps=4, max_steps=20 birlikte ne anlama gelir?
Cevap

Her ileri geçişte 1 örnek işlenir, 4 adımın gradyanı biriktirilip bir güncelleme yapılır (etkin batch 4). 20 güncelleme → ≈80 örnek, yani 800'lük eğitim kümesinin onda biri (epoch 0,1).

  1. model.config.use_cache eğitimde neden False, çıkarımda neden True?
Cevap

Cache (KV cache) üretim sırasında önceki token hesaplarını saklayıp hızlandırır ama bellek ister. Eğitimde gereksizdir ve gradient checkpointing ile çakışır; çıkarımda hız için yeniden açılır.

  1. Adaptör Hub'dan geri yüklenirken PeftConfig neden önce okunur?
Cevap

adapter_config.json içindeki base_model_name_or_path adaptörün hangi temel modelle (Qwen/Qwen3-8B) eğitildiğini söyler. Önce o temel model 4-bit yüklenir, sonra PeftModel.from_pretrained ile adaptör üstüne takılır.

  1. outputs[0, inputs["input_ids"].shape[1]:] satırı neden var?
Cevap

generate çıktısı girdi token'larını da içerir. Girdi uzunluğu kadar token atlanarak yalnızca modelin yeni ürettiği kısım decode edilir; böylece soru cevabın başında tekrar görünmez.
