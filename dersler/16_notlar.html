Ana kavramlar

  • Deployment (canlıya alma): Yerelde çalışan uygulamayı müşterilerin/başkalarının erişebileceği hale getirmek. Neden önemli: Yerelde çalışan bir demo başkasına gösterilemez; "binanın çatısı".
  • Not: Derste uygulama yerel LangGraph sunucusunda (127.0.0.1:2024) ve yerel Streamlit'te çalıştırıldı; bulut platformuna (LangSmith Deployment, Streamlit Cloud, Render vb.) gerçek yükleme adımı altyazıda yok.
  • RAG agent: Soruyu değerlendirip gerekiyorsa vektör veritabanından bilgi getiren bir tool'u çağıran, gerekmiyorsa kendi bilgisiyle cevap veren agent. (Hoca bunu "agentic RAG"dan ayrı bir şey olarak andı.)
  • Supabase: "Bulutta çalışan PostgreSQL". Veritabanı + vector eklentisiyle vektör veritabanı. İki bağlantı yolu: Supabase istemcisi (SUPABASE_URL + SUPABASE_SECRET_KEY) veya doğrudan PostgreSQL (DATABASE_URL).
  • psycopg: Python'dan PostgreSQL'e bağlanma kütüphanesi. with ile açılan bağlantı blok bitince otomatik kapanır.
  • Cursor (imleç): Veritabanında SQL çalıştırmayı sağlayan nesne (cursor.execute, fetchone).
  • Supabase MCP: Supabase'in MCP sunucusu; Claude Code / Codex / Cursor / VS Code'a eklenince veritabanıyla doğal dilde konuşulabilir (Codex'te 20 tool göründü). Neden önemli: Kod yazmadan sorgu/inceleme.
  • LangSmith: LangChain ekosisteminin izleme (tracing) aracı: token, maliyet, model, girdi/çıktı, metadata, agent adımları. Neden önemli: İzlemeyen sürpriz faturayla karşılaşır; agent'ın nasıl çalıştığını görmek, kurmak kadar önemli.
  • pgvector / vector eklentisi: PostgreSQL'i vektör veritabanına çeviren eklenti; VECTOR(1536) sütun tipi ve <=> (kosinüs uzaklığı) operatörü.
  • HNSW indeksi: Vektör aramalarını hızlandıran yaklaşık en yakın komşu indeksi (USING hnsw (embedding vector_cosine_ops)). Normal indeksler vektör aramasını hızlandıramaz.
  • match_documents: SQL'de yazılan arama fonksiyonu: sorgu embedding'i + kaç sonuç + metadata filtresi → en benzer dokümanlar ve benzerlik skoru.
  • RLS (Row Level Security): Satır düzeyi güvenlik; documents tablosunda da açıldı (policy tanımlanmadı, secret key/servis rolü ile erişiliyor).
  • Embedding modeli text-embedding-3-small: OpenAI'ın 1536 boyutlu vektör üreten modeli; tablo boyutu bununla aynı olmalı.
  • SupabaseVectorStore: LangChain'in Supabase sarmalayıcısı; add_documents ile metni embedding'e çevirip yazar, similarity_search ile sorguyu embedding'e çevirip match_documents'ı çağırır.
  • Tool (@tool): Fonksiyonu agent'ın çağırabileceği araca çevirir; docstring, modelin aracı ne zaman kullanacağını anlamasını sağlar.
  • create_agent: LangChain'in model + tools + system prompt'tan agent (LangGraph graph'ı) oluşturan fonksiyonu; model "sağlayıcı:model" biçiminde yazılır.
  • langgraph.json: LangGraph sunucusuna hangi graph'ın hangi adla yayınlanacağını ve .env'i söyleyen yapılandırma.
  • Agent Server / langgraph dev: Graph'ı HTTP API olarak sunan yerel sunucu (http://127.0.0.1:2024). (Not: komut altyazıda geçmiyor; langgraph-cli[inmem] bağımlılığı ve adres bunu gösteriyor.)
  • Thread / Run / Assistant (eklenen dokümanların içeriği): Thread = konuşma geçmişini ve state'i saklayan kalıcı konteyner; Run = assistant'ın bir kez çalıştırılması (thread üzerinde çalışırsa state kalıcı olur); Assistant = graph'ın model, system prompt ve tool ayarlarıyla yapılandırılmış çalıştırılabilir sürümü.
  • LangGraph SDK (get_sync_client): Agent Server'a Python'dan istek atan istemci (threads.create, runs.stream).
  • Streamlit session_state: Sayfa her etkileşimde yeniden çalışsa da oturum boyunca değer saklayan sözlük; thread ID ve mesaj geçmişi burada tutulur.

4) scripts/setup_database.py — vektör şeması (özet)

SET LOCAL search_path = public, extensions;
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE IF NOT EXISTS documents (
    id BIGSERIAL PRIMARY KEY,
    content TEXT NOT NULL,
    metadata JSONB NOT NULL,
    embedding VECTOR(1536) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS documents_embedding_hnsw_idx
ON documents USING hnsw (embedding vector_cosine_ops);

-- match_documents(query_embedding VECTOR(1536), match_count INT, filter JSONB)
SELECT d.id, d.content, d.metadata,
       (d.embedding::TEXT)::JSONB AS embedding,
       1 - (d.embedding <=> query_embedding) AS similarity
FROM documents AS d
WHERE d.metadata @> filter
ORDER BY d.embedding <=> query_embedding
LIMIT match_count;

ALTER TABLE documents ENABLE ROW LEVEL SECURITY;

(Python dosyasında her ifade ayrı cursor.execute(...) içinde; tam hali Ders Metni'nde.) - search_path → nesneler public'te oluşur, vector tipi extensions şemasından bulunur. - CREATE EXTENSION ... vector → PostgreSQL'e vektör tipi ve operatörleri ekler. - IF NOT EXISTS → betik tekrar çalıştırılınca "zaten var" hatası vermez. - VECTOR(1536) → embedding modelinin boyutuyla aynı olmak zorunda. - NOT NULL → içerik, metadata, embedding, tarih boş geçilemez. - hnsw ... vector_cosine_ops → kosinüs uzaklığına göre hızlı arama indeksi. - $$ ... $$ → fonksiyon gövdesi; LANGUAGE sql → SQL ile yazıldığını belirtir. - metadata @> filter → metadata filtreyi içeriyorsa (ör. {"chapter": 9}); varsayılan '{}' her satırı geçirir. - <=> → kosinüs uzaklığı; küçük = daha benzer. 1 - uzaklık = benzerlik skoru. - ORDER BY ... LIMIT match_count → en benzer k doküman. - (embedding::TEXT)::JSONB → Not: vektörü LangChain'in okuyabileceği JSON'a çeviriyor (fonksiyonun dönüş tipi embedding JSONB). - ENABLE ROW LEVEL SECURITY → satır düzeyi güvenlik açık.

Çalıştırma: uv run scripts\setup_database.py (Windows) / uv run scripts/setup_database.py (Mac).

8) src/deployment_demo/agent.py

@tool
def search_course_notes(query: str) -> str:
    """AI Engineering Bootcamp ders notlarında anlamsal arama yapar."""
    documents = vector_store.similarity_search(query, k=3)
    if not documents:
        return "Ders notlarında ilgili bilgi bulunamadı."
    return "\n\n".join(document.page_content for document in documents)

agent = create_agent(
    model="openai:gpt-4.1-mini",
    tools=[search_course_notes],
    system_prompt=(
        "Sen AI Engineering Bootcamp ders asistanısın. "
        "Ders içeriğiyle ilgili sorularda önce "
        "search_course_notes aracını kullan. "
        "Bulamadığın bilgiyi bulmuş gibi söyleme."
    ),
)
  • @tool + docstring → model aracın ne işe yaradığını açıklamadan öğrenir.
  • from .vector_store import vector_store → aynı paket içinden göreli import.
  • if not documents → boş sonuçta açık bir mesaj döner; model "bulamadım" diyebilir.
  • "\n\n".join(...) → 3 dokümanın metnini tek bağlam metni olarak modele verir (metadata gönderilmez).
  • model="openai:gpt-4.1-mini" → sağlayıcı:model biçimi; yanlış yazım hataya yol açar (derste konuşuldu).
  • system_prompt → ders sorularında önce tool'u kullan; uydurma (halüsinasyona karşı kural).

Hocanın vurguları & pratik kurallar

  • Ayrıntıyı ezberlemeyin, mimariyi bilin: SQL fonksiyonu, HNSW vb. kodları yapay zekâ yazabiliyor; sizin işiniz mimariyi kurmak ve genel çalışma mantığını bilmek.
  • Ama yapay zekâya her şeyi bırakmayın: Basit işlerde bile çok token harcayabiliyor, uzun yollardan gidiyor. Konuları genel olarak bilmek maliyeti düşürür.
  • İzleme şart: Agent'ı kurmak yetmez; LangSmith ile token, maliyet, model ve adımları izleyin, yoksa sürpriz faturayla karşılaşırsınız.
  • Kendi API anahtarlarınızla çalışın: AI mühendisinin çalışma alanı API; sohbet arayüzleri esnek değil. Hocanın paylaşılan .env'i yalnızca bu ders içindi.
  • with ile veritabanı bağlantısı açın; kapatmayı unutma riskini ortadan kaldırır.
  • Kodla tablo oluşturmak arayüzden oluşturmaktan daha kolay ve tekrarlanabilir.
  • Kopyala-yapıştırda görünmez karakterler girinti/sözdizimi hatası yaratır; satırı temizleyin veya yeniden yazın.
  • Sunucu terminalini kapatmayın; istemciler (test betiği, Streamlit) ikinci terminalde çalışır.
  • Fine-tuning donanımı: LoRA/QLoRA belleği çok azaltır; asıl darboğaz VRAM; RAM taşmayı destekler ama çok yavaş; çekirdek sayısı da önemli.
  • RAG mı fine-tuning mi? Ayrı alanlar; projeye göre seçin (maliyet/performans), hibrit de olabilir.
  • Yerel LLM'ler: veri gizliliği ve artan abonelik fiyatları nedeniyle önemli; 27B–35B civarı modeller kişisel bilgisayarda çalışabiliyor.
  • Model tercihi (hocanın görüşü): Kod ve problem çözmede Opus, Türkçe yazımda ChatGPT daha iyi; karşılaştırma için Artificial Analysis.
  • Öğrenme: Her konu ayrı bir bootcamp; ellerinizi kirletin, araştırın, farklı projeler yapın. Andrew Ng: bu konular artık beyaz yakalılar için temel bilgi.
  • Mülakat: Büyük şirketlerde sorular ağırlıklı olarak veri yapılarından gelir.
  • Bitirme projesi:
  • Süre: yaklaşık bir hafta — "haftaya Cumartesi (31'i)", belki "1–2'sine kadar" [belirsiz]. (Not: Perşembe 29'u tatil dendiğine göre 31 Ekim Cumartesi olmalı.)
  • Hoca bu hafta (muhtemelen Cuma) öğrencilerle birebir proje fikri konuşacak.
  • Teslim: İsteyen son derste sunum yapar, isteyen proje dosyalarını doğrudan hocaya gönderir.
  • Proje yapana başarı sertifikası, yapmayana katılım sertifikası; proje CV'ye eklenir.
  • Fikir: Derste yapılan projeyi geliştirmek (15. derste önerildiği gibi); sadece izleyenler hocanın paylaşacağı çalışmayı adım adım yapıp kendileri geliştirebilir.

  1. Supabase'e bağlanmanın iki yolu nedir ve her biri hangi ortam değişkenlerini kullanır?
Cevap

Supabase istemcisi (create_client(SUPABASE_URL, SUPABASE_SECRET_KEY)) ve doğrudan PostgreSQL bağlantısı (psycopg.connect(DATABASE_URL)). Bu projede vektör store istemciyi, şema kurulumu ise doğrudan PostgreSQL'i kullandı.

  1. psycopg.connect(...) neden with bloğuyla açıldı?
Cevap

Veritabanı bağlantısının iş bitince kapatılması gerekir; with bloğu bitince bağlantıyı (ve cursor'ı) otomatik kapatır, ayrıca close() çağırmaya gerek kalmaz.

  1. documents tablosundaki VECTOR(1536) sayısı nereden geliyor, farklı olsaydı ne olurdu?
Cevap

text-embedding-3-small modelinin ürettiği vektör boyutu 1536'dır. Boyut uyuşmazsa eklemede/aramada boyut hatası alınır; başka bir embedding modeline geçilirse tablo ve fonksiyon tipi de değişmelidir.

  1. HNSW indeksi ve <=> operatörü ne işe yarar?
Cevap

<=> iki vektör arasındaki kosinüs uzaklığını hesaplar (küçük = benzer; 1 - uzaklık benzerlik skoru). HNSW (vector_cosine_ops) bu uzaklığa göre en yakın komşuların hızlı bulunmasını sağlayan indekstir; normal indeksler vektör aramasını hızlandıramaz.

  1. match_documents fonksiyonunun üç parametresi nedir, filter nasıl çalışır?
Cevap

query_embedding (sorgu vektörü), match_count (kaç sonuç), filter (JSONB metadata filtresi). metadata @> filter ile metadata filtreyi içeren satırlar aranır; varsayılan '{}' tüm satırları kapsar (ör. {"chapter": 9} ya da yıl filtresi).

  1. vector_store.similarity_search(query, k=3) çağrıldığında arka planda hangi adımlar olur?
Cevap

Sorgu OpenAI embedding modeliyle vektöre çevrilir → Supabase'deki match_documents fonksiyonu çağrılır → kosinüs uzaklığına göre en yakın 3 doküman (içerik + metadata) döner.

  1. add_documents.py'de from src.deployment_demo... yazmak neden hata verdi?
Cevap

src sadece kaynak kod klasörüdür; uv proje yapısında kurulan paketin adı deployment_demo'dur. Doğru import from deployment_demo.vector_store import vector_store.

  1. Agent'ın system prompt'undaki "Bulamadığın bilgiyi bulmuş gibi söyleme" cümlesi ve tool'daki if not documents kontrolü birlikte neyi amaçlar?
Cevap

Halüsinasyonu azaltmak: Tool boş sonuçta açıkça "ilgili bilgi bulunamadı" döndürür, prompt da modelin bu durumda uydurmamasını ister. Ayrıca prompt ders sorularında önce tool'un kullanılmasını söyler.

  1. langgraph.json'daki "agent": "deployment_demo.agent:agent" satırı ile client.runs.stream(thread_id, "agent", ...) arasındaki ilişki nedir?
Cevap

langgraph.json deployment_demo/agent.py içindeki agent nesnesini sunucuda "agent" adlı graph olarak yayınlar; istemci runs.stream'de bu adı vererek o graph'ı çalıştırır.

  1. Streamlit uygulamasında thread ID'yi session_state'te saklamasaydık ne olurdu?
Cevap

Streamlit her etkileşimde betiği yeniden çalıştırdığı için her mesajda yeni thread oluşturulurdu; agent önceki konuşmayı hatırlamaz, her soru yeni bir sohbet gibi olurdu.

  1. stream_mode="updates" ile stream_mode="values" farkı derste nasıl kullanıldı?
Cevap

updates her adımda yalnızca değişikliği verir (test betiğinde model → tool → model adımlarını görmek için). values her adımda tam state'i verir; Streamlit'te son değerdeki son mesaj nihai cevap olarak alındı.

  1. LangSmith izlemesini açmak için kodda ne değiştirildi?
Cevap

Kodda değişiklik gerekmedi; .env'e LANGSMITH_TRACING=true, LANGSMITH_API_KEY, LANGSMITH_PROJECT eklendi ve load_dotenv() ile yüklendi. LangChain çağrıları otomatik olarak o projeye trace olarak düştü.
